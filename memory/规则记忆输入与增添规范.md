# 规则记忆输入与增添规范

本文件是规则库的维护入口，规定如何把用户提供的经验或制作要求整理成可读取、可触发、可核查的规则。它不是一条生产规则，不登记到 rules 数组，不要求每格加载。新增或修改规则时读取；正常生产按索引 stages/load_policy 预读阶段基准并按触发条件补读专项正文。

## 1. 日常怎么提供新规则

你可以直接用自然语言描述。维护执行者先判断归属：固定流程归Skill合同，技术可判定项目归共享脚本，跨作品视觉方法归本库，本话事实归生产记录；再检查既有条目、补齐阶段与触发/验收要求，按授权写入。用户不必手工编 JSON 或计算哈希。

推荐复制填写：

```text
规则记忆输入
规则记忆目录：【规则记忆绝对目录】
处理方式：仅整理候选 / 写入候选 / 写入并启用 / 修改既有条目 / 停用既有条目
规则内容：希望强制做什么、禁止什么、为什么。
适用情况：画面实际发生哪些情况才需要执行。
不适用情况：容易误触发的情形。
责任阶段：可先用中文写，维护者映射成合法阶段。
执行阶段：哪些阶段需准备、落实或检查。
读取方式：阶段预读 / 命中再读；未指定时默认命中再读。
验收标准：实际图中怎样算通过，怎样算失败。
必需材料：是否确实需要站位图、参考或相邻格证据；没有则写无。
冲突处理：是否替代某条旧规则；与锁定剧情/批准资产冲突时如何处理。
```

未提供的信息只在可以从内容合理推断时补齐；影响规则意义的歧义不能猜成硬要求。不要把通用要求绑定某个人物、某话或某本书。明确要求入库启用时，不重复索要相同授权；只要求规划或整理时，不写入或启用。

## 2. 什么内容可以入库

允许：换作品、换话、换角色后仍成立的制作方法、画面约束和检查动作。例如人物在床上时核对承托面，镜面采用磨砂，相邻格检查真实观看角度和景别差异。

不允许：书名、人物名、某话服装与伤势、某格站位和坐标、某次修复结果、特定剧情事实。这些信息保留在脚本、资产、镜头或本次 QA 中。发现一个失败案例，不等于可以自动将它推广为所有画面的通用禁令。

入库前说明：去掉原作品和角色信息后为何仍成立；明确适用条件、误触发边界、检查方法及是否和旧要求冲突。机器结构校验不能代替这一步语义判断。

## 3. 标准处理顺序

1. 读取本文件、记忆索引，以及与拟增规则重叠的正文；只读相关条目，不全库重读。
2. 去掉案例事实，形成通用方法。一个条目围绕一个能独立触发和检查的问题；一批内容覆盖不同条件时拆分。与旧条目同义则修改或合并，不新增重复检查。
3. 确定责任阶段、所有执行阶段、语义触发标签和每阶段检查项目。责任阶段必须在执行阶段内。一般规则选择 on_match；确需让执行者进入阶段就掌握的基础视觉方法才选择 stage_baseline，避免把全库设为预读。读取方式不改变实际适用条件。
4. 对照当前 Skill 的脚本合同。明确哪些字段会被脚本检查，哪些判断需要执行者实际阅读/看图，不声称自然语言已成为自动视觉识别。
5. 按授权创建正文与索引条目。普通新提案先 candidate；用户已明确要求作为当前制作标准启用的，完成上述检查后可 active，并在 admission.basis 如实记录授权来源。
6. 正文计算真实 SHA-256，登记到索引；更新既有条目时提高版本号。一次维护完整交付正文和索引，不留下未登记的生产规则文件。
7. 运行规则库结构与哈希校验，再核对命中、不命中、边界和冲突情形。完成后报告新增/修改 ID、状态及对应文件。

正常生产 agent 对规则库只读。只有得到规则维护授权的执行者才可修改；相邻图片和具体错误事实不会自动回写为通用记忆。在途生产涉及规则改版时，由总控先收回结果并协调版本；不能静默改验收条件，不能给旧图自动补 PASS。

## 4. 文件和阶段约定

生产规则正文位于 `规则/<责任阶段中文目录>/MEM-编号_名称.md`。当前有镜头、生图两类目录，新增其他责任阶段时可按需建立对应目录。目录代表责任归属，不代表正文只在该阶段执行。

| 索引阶段值 | 中文含义 | 适用动作 |
|---|---|---|
| input_audit | 输入审计 | 输入来源与前置事实检查 |
| visual_assets | 视觉基准/资产 | 人物、衣装、场景和样例依据准备 |
| shot_design | 镜头设计 | 动作、机位、空间、裁切和连续性设计 |
| generation | 生图 | 冻结输入、参考、实际提示词及调用前检查 |
| image_review | 图片验收 | 对实际返回图与相关参考进行检查 |

当前流程已将记忆记录检查接入镜头、生图、图片验收；输入审计和视觉资产规则由对应 Skill 显式执行 rule_memory check。仅在索引加一个阶段名，不代表所有工具已自动支持该阶段检查。

## 5. 正文统一写法

维护者按以下结构写成具体规则，可删去确实不适用的小节：

```markdown
# 规则名称

适用：实际画面/操作满足什么条件。
不适用：关键词误召回、不可观察或特殊范围如何处理。

要求：必须做什么、禁止什么；描述可观察的结果，不堆抽象形容词。

镜头阶段：准备什么依据、设计什么可见关系。
生图阶段：核对什么，哪些具体约束进入实际提示词。
图片验收：看哪些实际部位、与哪些依据比较、失败时如何处理。

检查项目：逐项列出与索引 checks 相同的英文标识及中文含义。
必需材料：没有则明确无需新增；需要时说清用途与复用条件。
冲突处理：与旧规则/锁定剧情/批准依据的关系，不能擅改事实。
```

不得要求画外部分“看图通过”。同角色表情比较需脸部可比；只有相邻关系成立才做相邻比较；对白提床/镜子不能当作它在画面里可见。确实不可观察时如实记录边界，不能把缺证据伪装成通过。

## 6. 索引登记格式

登记位置是记忆索引.json 的 rules 数组。当前索引顶层 loading_policy=stage_baseline_loading_v1，与使用配置 memory.loading_policy 和生产 memory_source.loading_policy 一致；triggered_rules_v1 的执行触发不变。给正文命名与填完索引是一次完整入库，不能只建文件。每条必填：

| 字段 | 填写要求 |
|---|---|
| id | 唯一且不复用，延续 MEM 编号；修改旧条目保留原 ID |
| title / version | 清楚的问题名称 / 版本字符串；变更内容或执行行为都提高版本 |
| status | candidate 候选、active 生效、disabled 停用 |
| scope | 固定 cross_work |
| primary_stage / stages | 一个责任阶段 / 非空合法执行阶段数组 |
| load_policy | stage_baseline 进入 stages 预读；on_match 实际命中再读。只管读取，不免除 trigger 或增加适用范围 |
| admission | portable=true、contains_story_facts=false、rationale 通用性依据、basis 真实授权来源 |
| trigger.any_tags | 实际画面语义标签数组；无标签时可为空 |
| trigger.any_visual_terms | 关键词辅助召回数组；无关键词时可为空；两类不能同时为空 |
| trigger.semantic_condition | 推荐填写：哪些实际情形必须标记该标签，哪些不应标记 |
| requirements | stages 中每阶段都填写 checks、artifacts、prompt_constraints |
| file | 库内相对路径与真实正文 sha256，不能越出库目录 |

下面是结构模板，尖括号内容是填写位置，**未替换为真实内容和哈希前不能登记**：

```json
{
  "id": "<未占用的MEM编号>",
  "title": "<规则名称>",
  "version": "1.0.0",
  "status": "candidate",
  "scope": "cross_work",
  "primary_stage": "generation",
  "stages": ["shot_design", "generation", "image_review"],
  "load_policy": "on_match",
  "admission": {
    "portable": true,
    "contains_story_facts": false,
    "rationale": "<为何脱离原案例仍成立>",
    "basis": "<用户授权或候选来源；不虚构确认>"
  },
  "trigger": {
    "any_tags": ["<具体语义标签>"],
    "any_visual_terms": [],
    "semantic_condition": "<执行者在什么画面条件下须填写此标签>"
  },
  "requirements": {
    "shot_design": {"checks": ["<check_id>"], "artifacts": [], "prompt_constraints": false},
    "generation": {"checks": ["<check_id>"], "artifacts": [], "prompt_constraints": true},
    "image_review": {"checks": ["<check_id>"], "artifacts": [], "prompt_constraints": false}
  },
  "file": {"path": "<规则目录中的相对路径.md>", "sha256": "<实际64位SHA-256>"}
}
```

checks 使用稳定、可解释的检查标识，正文解释每一项，不能只写“质量好”。各阶段可以使用不同项目，模板同名只是展示结构。检查记录必须逐项给出实际依据。

artifacts 没有真实必要性时填 []；床规则的 spatial_diagram 才是当前明确必需的辅助图类型。脚本会查必需材料的存在、哈希与 reviewed 记录；spatial_diagram 另查可解析的图像文件。新增其他类型只能先做到通用存在/哈希检查，若需要额外语义或格式校验，须单独明确实现范围，不能假定已有。

prompt_constraints=true 时，执行者记录的约束原句必须存在于本格实际 prompt。布尔值本身不生成提示词，也不能证明所有语义已准确表达。

## 7. 触发后怎么执行，避免漏读和滥读

启动读取轻量索引。进入阶段运行 load-stage，预读当前 active 且 load_policy=stage_baseline 的正文；当前为 MEM-005/006 的镜头、生图、图片验收阶段。其余八条按实际命中加载。执行者按当前阶段、批准画面和上下文判断 trigger.semantic_condition，写入本格 memory_tags；逐格 load 返回阶段基准与实际命中的并集，已读版本仅返回缓存状态。select、执行记录和图片 QA 仍只列实际命中，预读人体方法不把空景变成人体格。结构已明确的可见对象会派生 visual_subjects_present，真实相邻关系使用同一上下文入口；返修按实际operation触发。脚本不自动看图或猜人体/床/镜面等语义。

标签冻结在 B 镜头审查材料中，执行包继承。符合条件却漏标会导致不触发，应在镜头审查检查覆盖性；返回图又出现未预期条件时记录问题并更新受影响输入/验收，不在已批准文件里静默补写。

阶段入口与逐格读取共用同一 agent、同一运行缓存，同一版本正文不重复输出；新 agent、上下文丢失或版本变化须重读，使用新 run-id 或 reload。缓存放本次 RV，不能写入库。关键词只是召回，误命中可提供 NOT_APPLICABLE 原因与依据；语义标签已命中不能如此豁免。无适用标签也填写 []，而不是删掉来源或字段。命令见 [规则记忆合同](~/.codex/skills/vertical-comic-preproduction/references/rule-memory.md)。

shot_design 执行记录位于批准镜头的相应 memory_applications；generation 位于冻结执行包；image_review 位于实际返回图的 QA memory_review 并绑定图片哈希。所有必需检查与证据、材料、实际提示词约束未齐时保持 MEMORY_HOLD。技术记录完整不等于图像正确，也不代替规定的用户审查。

## 8. 版本、冲突和启停

修改既有规则：先核对实际当前文件，保留 ID，更新 version、正文哈希以及必要的触发/检查内容。索引条目签名包含触发和要求，行为变更会使对应旧执行记录失效；只复核受影响规则、格和依赖，不全量重生成。

修改 load_policy 也提高 version；未改变正文时保留原 file.sha256，不为读取方式改写判据。当前十条登记到 1.1.0，正文、触发与检查项目未变。旧冻结来源未声明读取扩展时只接受未升级的旧索引；新来源/索引不一致保持 HOLD，不能静默添加字段、改旧批准或把预读当验收。升级在新 RV 核验受影响版本、原例外与批准依据。

重复要求合并到已有条目；同一场景的通用原则和专项检查可以并存，但应写清互补关系。旧规则更宽、新要求更严时，写清替代范围和真实用户依据，不能让执行者自行选择较宽标准。停用设 disabled，不删除历史 ID。

用户当前明确指令优先于旧 Skill/旧记忆的一般约定；通用规则不会自行授权改写锁定脚本或批准资产。遇到真实冲突，记录具体依据和影响范围，按用户授权处理。普通制作问题不要新增无依据的审批停点。

当前 MEM-010 已按用户明确要求规定：相邻两格机位视角与景别同时有可观察变化，替代旧版“同景别正反打可直接通过”的宽松约定。镜面磨砂和微表情变化也不得用旧模板绕过。

## 10. 校验命令与完成标准

只读校验当前库：

```bash
python3 -B ~/.codex/skills/vertical-comic-preproduction/scripts/rule_memory.py --root 【规则记忆绝对目录】 --mode validate-library
```

修改正文后可计算其哈希（路径换成实际修改文件）：

```bash
shasum -a 256 "【规则记忆绝对目录】/规则/生图/MEM-008_镜面统一磨砂且不呈现真实反射.md"
```

用维护者准备的临时单格 JSON 验证触发（文件必须为单格对象，不能是整包 panels 数组）：

```text
python3 -B ~/.codex/skills/vertical-comic-preproduction/scripts/rule_memory.py --root 【规则记忆绝对目录】 --stage generation --panel <实际临时单格JSON绝对路径> --mode select
```

验证至少包含实际适用、实际不适用、仅对白提及、关键词误召回等与本条相关的情况；相邻规则另核对首格、批次边界和比较对象。机器可验证路由/结构/版本绑定，不能证明自然语言条件判断或实际图片合格。完成标准是正文/索引一致、当前哈希正确、状态及授权清楚、触发范围可解释、每个检查动作可落实。

## 规则归属与检查复用

正式规则只维护一份MEM正文和对应机器索引。Skill与质量说明引用ID，不复制另一套镜头/视觉判据；基础六项QA与固定合同始终执行。MEM-010当前判据保持原样，旧宽松描述只在其原冻结合同范围适用。

半话语义审计的rule_triggers保留matched_rules（memory_id/rule_signature）；模板从当前命中集生成，仍需实际核对且不预填PASS。启用人体规则且有可见角色时，填写human_figure_visible的decision与具体evidence；APPLIES须与冻结标签一致，局部人手也按可见部分适用，真实非人体角色说明不适用依据。

实际图片用inspection_plan组织一次观察，原三类QA记录逐项核对；共用同一观察不表示判据等价，不能用身份PASS自动推导道具PASS。索引/匹配仅在一个门禁进程内按实际内容版本复用；正文继续按agent/运行/版本加载，检查结论不在路由缓存中保存。

仅调整维护说明、读取路由或引用关系而未修改条目正文/判据时，不机械提高全部规则版本。正文或规则执行行为变更须按既有版本流程处理。旧生产RV的冻结证据保持；共享检查器更新后按新RV升级说明核验工具与受影响依据。
