# 场景和缺失资产处理

## 现有资产优先

匹配或补画人物之前先读 [identity-confirmation.md](identity-confirmation.md)，将原脚本称呼对应明确角色名称、唯一 ID 和人物关系；例如“傅妈”尚未确认全名/明确人物时，保持 `IDENTITY_HOLD` 并暂停询问。之后单独确认本话样貌、服装、年龄/时期及伤势状态；认对人而状态不明仍是 `APPEARANCE_HOLD`。场景先确认地点归属与时期/状态，不明时 `SCENE_IDENTITY_HOLD`。不要用相似图、文件名或亲属关系推测替代。

实际打开图片核对，登记资产的本书 ID、所属角色/场景、适用状态、用途、版本、哈希与范围匹配的确认依据，绑定后才进入下游；更换依据或状态须重审受影响格子。一次出镜不免上述确认。

2026-09-29用户补充：仅出现一次的人物、场景、道具不需要独立资产。先按本书可取得脚本统计真实出镜次数，使用统一对象身份去重，不把画外声音算出镜，也不把同一场景连续多格算作一次。一次出镜只免独立资产：本格仍须有明确外观、尺寸关系、画面位置、光线和遮挡；若该元素已有合适资产可以复用。不得凭空认定未知角色只出现一次。

先做资产盘点，再决定补图。每个场景和角色资产标记 `APPROVED`、`CANDIDATE`、`HOLD` 或 `MISSING`。禁止用相似角色或相似场景静默替代缺失资产。

## 九宫格资产任务

九宫格任务必须同时产生：

- `scene_ledger.json`；
- 九宫格联系图；
- 八个视角的独立高清视图；
- 每个视角的相机方位和可见区域记录；
- 结构一致性检查表；
- 光源和材质一致性说明；
- 未知结构和待用户确认项。

Codex 逐格生图优先选与当前方向匹配的独立场景视图，九宫格联系图留作资产选择和审阅。人物参考匹配批准身份及当前衣装状态；细节图只补本格必要信息。场景/人物板的完整宽景或全身不能扩大批准裁切。

光照方向固定在场景坐标而不是每张画面的左上角。相机改变后，画面上的亮暗左右关系可以随真实空间改变，但主光源在世界中的方向不能漂移。

## 缺失资产

缺失资产有三种处理：

1. 现有资产可通过裁切/旋转/组合解决：登记复用方式；
2. 需要新图但有授权图像生成工具：生成 `CANDIDATE`，保留提示词、参考图、版本和结果；
3. 需要新图但没有工具、来源或结构依据：写 `ASSET_HOLD` 任务单，不伪造完成。

场景补图确认前，下游镜头若依赖该资产必须保持 HOLD；不能一边标记资产缺失，一边生成看似确定的提示词包。

For staged production, rendering style comes from the current book's approved comic samples; scene templates control board layout/labels only. Follow [stage-asset-production.md](stage-asset-production.md) and [execution-compatibility.md](execution-compatibility.md) when these roles conflict.

同书同状态同用途且原批准有效的真实原图直接复用。技术复制或别名变化不增加A审；真实新增身份、衣装或布局仍交A。共用缺资产只准备一份并集中展示，独立就绪话继续。
