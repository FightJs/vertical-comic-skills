# 全话画幅比例与交错分布

正文逐格启用 `frame_ratio_policy: content_balanced_ratios_v1`。这是固定生产规格，随镜头/生图包/验收始终执行，无须命中记忆才加载。人物与场景资产板继续按其批准模板规格制作。

## 选幅与全话约束

每格从 **9:16、3:4、4:5、1:1、5:4、16:9** 选择，记录 `frame_ratio` 和具体 `frame_ratio_reason`。理由应说明人物、动作、必显物件、空间方向或焦点如何适应该画幅；按现有批准裁切取景，不为配比例移动场景物件、扩成全身、漏掉接触/同时反应或改原文。

| 比例 | 可考虑的画面需求 |
|---|---|
| 9:16 | 纵向动作链、上下层次、狭长空间；是否露全身由批准裁切决定 |
| 3:4 | 人物反应、上身动作与必要环境锚点 |
| 4:5 | 紧凑人物互动、表情和手部并存 |
| 1:1 | 集中的脸部、道具或局部反应 |
| 5:4 | 横向双人关系、并列动作与空间距离 |
| 16:9 | 多组人物、房间两端或横向场景信息 |

这些是选幅提示，每格仍根据实际内容判断。禁止整话统一画幅或只填“适合内容”。源格序保持不变，改变的是逐格画幅选择。

“竖版比例大于四分之三”指**每话竖版格数占总格数严格大于75%**。竖版为9:16、3:4、4:5；1:1不计竖版。不是要求图片宽÷高大于0.75，也不把六种比例各分六分之一。

- N格至少 `floor(3N/4)+1` 格竖版：30格至少23格，35格至少27格。
- 三种竖版比例数量均衡，最多相差1格；使用的方/横组三种比例同样均衡，最多相差1格。小话可以不使用所有六种比例。
- 相邻格采用不同画幅；按各自数量交错分布，不能把方形/横版集中堆在一段或末尾。
- 分布检查按源序前缀比较实际数量与全话配额：方/横合计偏差最多1格；单种比例容许2格局部内容偏差。该容差用于内容适配，数量均衡、竖版占比与相邻交错仍须通过。

30格数量示例：9:16/3:4/4:5为8/8/7格，1:1/5:4/16:9为3/2/2格。35格可以9/9/9与3/3/2。按内容确定各格，不把数量例子当固定循环模板。内容与规格冲突时在原B审查点集中处理具体冲突，不静默统一比例或重排剧情。

## 一次规划，两半共用

读取完整源稿并核对整话必要人物、衣装和场景资产后，在全话B批准前准备一份全话比例计划，逐格按内容选幅。它是源序、比例和选幅理由小表，整话使用同一批准版本；受影响范围缺项单列待补。

state保存 `frame_ratio_policy` 和 `frame_ratio_plan={path,sha256}`。计划JSON含 `policy`、`book_id`、`episode_id`、`source_snapshot`、完整 `panel_ids`、`panels`；每行含原技术 `panel_id`、`frame_ratio`、`frame_ratio_reason`。源稿快照与书话、格数、格序均准确绑定。

```text
python <scripts>/frame_ratio_plan.py --state <本话/00_输入审计/生产流程.json> --write-template <本话/00_输入审计/全话画幅计划.json>
python <scripts>/frame_ratio_plan.py --state <本话/00_输入审计/生产流程.json>
```

模板比例为空，状态UNPLANNED_NOT_APPROVED；执行者逐格填内容依据，再登记真实计划哈希。第二条检查全话分布和源绑定，不生图、不授予批准。B审查包展示源序比例表、数量/竖版占比、选幅理由及冲突。B批准绑定计划文件版本，整话共用同一计划。

全话镜头及每次单格执行包保留相同根字段 `frame_ratio_policy/frame_ratio_plan/source_snapshot`；frame_ratio_plan与source_snapshot路径相对**本话根目录**。逐格字段复制本计划的ratio和reason，不能中途重新随机配比或默认9:16。单格包编译 `frame_ratio_execution_block=frame_ratio_plan.execution_block(panel)`，写入实际prompt、prompt.txt和逐格JSON。输出规格output_spec的宽高与本格比例配套，不能全话沿用同一9:16精确尺寸。

校准和普通返修保持批准比例、理由和计划引用。确需改比例时形成新版本、列受影响格并回B确认；技术PASS、返图成功或局部修正授权不允许自行改幅。已冻结的源稿、原请求/返回和批准证据不改。

## 图像验收

实际像素宽高须符合本格frame_ratio与已批准ratio_tolerance；更接近另一种比例或竖/方/横方向不符即IMAGE_RATIO_HOLD，不能靠放宽容差冒充通过。基础六项QA、批准裁切及必显信息照常核对。

```text
python <scripts>/make_generation_qa.py --package <本格包> --episode-root <本话根> --images <返回图目录> --output <新QA目录>
python <scripts>/frame_ratio_plan.py --state <生产流程.json> --actual
```

前一条创建未审QA并带全话**计划**统计；后一条在全部图片存在后按真实像素重算全话**实际**统计。计划多比例但实际通体同幅仍失败。D和跨话交付前执行实际全话分布检查，各话分别统计，不能用五话合计掩盖某话比例单一。

当前整话模式在D按完整源序统计竖版比例，严格超过75%；同时核对六种比例的按内容选幅和交错分布。已返回格可先核对单图比例，但不把局部统计冒充整话通过。旧半话RV仍按原C停点恢复。

旧RV没有标记时保留其原冻结合同；恢复时明确在新RV补全画幅计划、检查原图并确认变化范围，不伪改原批准。新任务读取当前使用配置的framing.policy自动启用。

## 核对实际工具输出能力

编译job的output_capabilities描述实际参数是否携带硬像素控制；它不证明工具保证精确尺寸，也不改变批准容差。工具未提供硬尺寸参数而要求零比例误差时，前期集中核对现有技术派生授权及内容容纳；需要取舍才提交准确范围。返回仍按原规格计算，微小偏差保留真实FAIL，不为比例反复重抽；没有信息完整裁切依据时留人工处理。
