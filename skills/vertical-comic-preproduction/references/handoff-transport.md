# 微信交接运输

正式release通过后，用安装版scripts/handoff_transport.py export --zip <原正式ZIP> --output <全新交付目录>生成最终运输文件。默认每文件不超过900000000字节，内容按SHA256无损去重，超限自动分卷。export从实际输出恢复并运行原正式目录校验后才返回VERIFIED_TRANSPORT；失败清除本次输出，不删除原包。保留返回的实际文件清单、大小及哈希作为交付记录。

一个ZIP时直接发送；分卷时发送目录内全部ZIP，各卷说明和索引内置，不发送半套。用户只需提供任一卷路径及输出目录，comic_start.py receive --zip自动识别、收集同目录其他卷、验证并恢复，再按原bind/rehearse生产。先更新接收端Skill；普通解压只能得到运输对象，不能直接生图。旧正式ZIP及完整原目录仍走原入口。

运输恢复原文件路径和字节，不重建原ZIP二进制；不重签批准、不改预算或UNKNOWN。新旧冻结生产工具保持原样。分卷索引校验检测损坏，不证明发送者身份。缺卷/重复/混卷/损坏停止受影响接收，准确报错。恢复原件保留在输出位置，失败不启动生产。

本版不裁减历史证据，不转换图片格式。采用900MB硬上限，实际压缩后每卷均检查大小。发布阶段只有全部运输文件生成并恢复验证通过才对用户报告完成；进度complete使用原正式ZIP并附--transport-receipt <运输验证.json>绑定完整运输集合；任一文件变化即失效，不把原ZIP就绪冒充运输完成。

推荐发布命令在原release参数后附加 --transport-output <全新交付目录>，自动完成发布后导出。容量可通过独立export命令的--max-file-bytes调整，最大900000000字节；不增加生产配置依赖。

新任务最终交付必须执行[完整交付与容量门禁](delivery-contract.md)：前期交接单ZIP优先、超限自动连续分卷，每文件不超过900000000字节；成品ZIP无容量上限、不因体积自动分包，并必须包含图片问题总览.csv及问题明细.csv。前期内容release之后走publish，成品目录export之后走普通ZIP发布；统一交付验收.json通过后才能finish-check/100%。容量失败只修装配与容器，不重新生图或降质；旧冻结运行不热升级。
