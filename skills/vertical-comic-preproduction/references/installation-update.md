# 五件套检查、更新与恢复

用户说“检查更新”“更新五件套”“恢复上一版”时读取本文。普通制作不自动联网查版本或热更新。默认稳定版来自FightJs/vertical-comic-skills正式Release；无需Git、gh或GitHub账号。用户规则贡献上传是独立功能，下载更新不启用它。

## 对话入口

```text
检查并更新条漫Skill五件套到最新稳定版。
保留本书配置和用户增补；正在运行的RV继续使用原冻结版本。
```

执行当前已安装总控scripts/update_skills.py，使用具备当前运行依赖的Python：

- `check`：只查询远程稳定版本、核对当前安装，输出当前/可用版本及本地差异；不下载安装。
- `update`：查询并下载稳定版ZIP和发布校验文件，在独立暂存目录核验后调用安装器；成功返回版本、来源及备份位置。
- `update --from-zip <安装包>`：用户明确提供的离线安装ZIP；校验包内清单及运行依赖，不声称已查询最新稳定版。这是Skill安装包，不是漫画生产交接包。
- `backups`：列出具有完整元数据的可恢复备份。
- `restore [--backup <ID>]`：恢复指定备份；不指定时选择最近完整备份。先验证备份、当前修改和保留的用户规则；恢复前再备份当前安装。

命令均可附`--codex-home <目录>`。未指定时按CODEX_HOME、当前总控所在托管安装、默认~/.codex依次定位；展示真实目录，歧义时不猜其他安装。不存在托管记录的手工安装允许显式安装，但不能自动覆盖它。不要将旧项目RV快照中的更新器当作当前安装入口。

用户明确要求更新即可完成普通无冲突更新，不再重复询问。只有检查请求不授予安装授权。`LOCAL_CHANGES`先列出准确文件及差异，按用户选择保留、导出或替换；不能自动加`--replace-existing`。用户规则目录是保留区，不把其中的合法增补当程序修改。兼容性冲突停止，不能删掉用户规则来“修复”。

## 版本和生效范围

默认stable；主动指定预览版时才使用`--channel preview`，查询main的明确提交并下载该提交，记录commit，不跟随用户贡献分支。稳定版落后于当前安装时返回AHEAD_OF_STABLE，不静默降级。正式Release缺安装附件时说明尚未发布统一安装包，不回退main、不宣称已更新。

当前Python依赖不满足时返回诊断与原安装保留结论；不自动修改系统Python。按README准备兼容环境再重试。匿名GitHub API限流时改用公开Release latest跳转定位同一稳定版，不要求登录、不改从main下载。网络/下载/哈希失败不改变安装；安装中失败恢复原文件。锁超时说明另一个安装/恢复正在执行，不删锁文件抢占。备份不自动清理。

新版五件套和内置规则只用于后续新运行。项目`.comic/books`、使用配置、源脚本、资产、批准、图片、请求、预算、UNKNOWN和冻结运行不属于安装目标。用户增补、贡献outbox及同步授权保留；恢复旧版也保留今天的用户增补，若旧版无法读取则停止恢复。

更新成功后建议在新的Codex轮次使用；当前对话可能已加载旧指令，不能声称已热切换。每次报告准确安装版本、发布来源、备份位置和旧RV不变结论。恢复是程序/内置库恢复，不回退剧情状态或批准。

## 维护者发布

PR和三平台检查通过并合并后，由维护者明确创建与VERSION一致的vYYYY.MM.DD.N标签。release.yml复用完整检查，生成固定命名的安装ZIP及SHA256附件并发布Release。构建拒绝夹带个人规则，不覆盖已有发布。合并本身不等于已发布；只有发布成功，普通用户的stable更新才会看到新版本。

旧版没有一句话入口：首次从正式Release下载新版安装ZIP，按README安装一次。此后直接使用对话入口。恢复只自动识别新增备份元数据的备份，历史旧文件夹保留供人工核对，不伪称可自动恢复。
