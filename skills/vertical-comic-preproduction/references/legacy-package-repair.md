# 已完成生图包的修复规则

两版修复器先执行 [identity-confirmation.md](identity-confirmation.md) 门禁。旧包必须先补齐真实身份/称呼关系/外观/场景确认及实际资产绑定；缺失或冲突时在创建新包前停止。可传 `--identity-root <本话确认依据根目录>`，默认旧包的父目录；修复授权及 `--accepted-basis` 不代替身份确认，不自动给“傅妈”等称呼补姓名。确认合同、逐格绑定与锁定正文须随新包保留；新增未决项继续 HOLD。

**先读 `repair-contract-v2.md`、`shot-framing.md` 和 [规则归属](rule-ownership.md)。旧版修复器仅做技术迁移，不能把候选变为可生图。本文原宽松正反打说明只用于其原冻结历史合同；启用当前规则的新任务按实际索引、正文及准确用户例外执行，不能用历史说明覆盖 MEM-010。保留一次出镜资产豁免、实际证据核验、脚本锁定和适用批准范围。**

有新 `framing` 时，旧版修复器将旧正文和负向词保留在审计字段，按新裁切重建执行正文，避免旧全景指令冲突。`LEGACY_PROMPT_REVIEW_HOLD` 解除前，核对既定画风等非构图约束与必显信息均完整迁移。两版修复器依赖同目录 `validate_preproduction.py` 与 `legacy_spatial_cleanup.py`，应保留完整脚本目录。

当旧包已经生成，但出现“相邻格只换动作、机位没有真正变化”“提示词只在 JSON 里写机位”“画幅被生图工具默认成 3:2”“参考图路径复制后失效”等问题时，不能直接覆盖旧包。

运行：

```powershell
python scripts/repair_prompt_package.py `
  --source <旧生图包> `
  --shot-manifest <镜头改编表或镜头候选表> `
  --output <新修复包>
```

修复器会：

- 保留旧包，只将当前有效参考与审计资料复制到新版本；旧正文变体、旧报告和旧压缩包不进入新执行目录；
- 将机位角度、景别、画幅比例、摄影机位置/朝向、高度/俯仰、镜头签名和实际可见区域写入真实 `prompt.txt`；
- 将场景、可见区域、人物画面位置、身体/头部朝向、视线、表情、动作、背景锚点、固定道具和遮挡关系写入 `画面内容锁定` 块；
- 归一化旧包中多写了一层包目录名的参考路径；
- 对 `HOLD`、未完成空间证明、未确定比例和缺失镜头依据保留 HOLD，不把文字补全当成物理证明；
- 在 `修复门禁报告.json` 中记录可直接生产格、仍需补证格以及下一步要求。

修复后必须先运行结构校验：

```powershell
python <工作区>/03_工具与模板/scripts/check_prompt_package.py --package-root <新修复包>
```

拿到底图后还必须运行：

```powershell
python scripts/make_generation_qa.py --package <新修复包> --images <B电脑返回底图目录> --output <QA目录>
```

未声明新模式的历史任务保留 P001–P003 原范围审查；新任务按其半话合同审查。焦点、裁切、可见信息及相邻差异使用当前适用判据；意外复制默认视图、违反适用规则或扩大为无依据全身/宽景时保持 HOLD。

## 2026-10-10 旧输入迁移

旧版逐格可见画面卡已停用。新的 `camera_composition` 普通参考使用独立别名（如 `@COMP_P012`），须有符合 Codex 合同的干净视角及真实核对证据；不得给旧卡改名或复用旧批准状态来绕过迁移。两版修复器移除旧字段、图像引用、别名及用途绑定，并写出 `旧空间输入迁移.json`；原索引和镜头表保留在新包 `sources/original_*` 中供审计。真实场景视图、站位图及镜头里的可见范围/左右/前后/裁切/接触记录保留。只解除单独的缺卡依赖；身份、脚本、镜头和混合空间问题继续 HOLD。JSON和文字不会再自动转换为参考图片。新版校验器发现停用输入会要求迁移；缺少这类图片不阻塞正常交接。
