# 速度优先的轻审核成品

新任务的默认返图审核为 `light_story_review_v1`。用户要求每图快速看一次，只修影响剧情理解的严重问题，最多一轮；不再用全面细节审查作为默认生产目标。这一规则优先于旧文档的六项QA、原尺寸局部取证、逐MEM观察、整话/跨话重复视觉复审及批量前真实返修演练要求。输入批准、源格完整性、真实调用记录仍沿用已有工具；不要重新制作已审输入。

## 启动与范围

`comic_start.py prepare` 默认使用轻审核，也可显式传 `--image-review-profile light_story_review_v1`。低层 `init_preproduction.py` 兼容入口需显式传 `--image-review-profile light_story_review_v1 --speed-policy bounded_stage_fallback_v1`。状态的 `image_review_profile` 冻结本次审核范围，接包自动沿用。用户明确要求全面精审时才使用 `--image-review-profile full`。没有该字段的旧冻结任务仍执行原审核；不要手改在途状态或将新QA装入旧包。

前期继续复用批准资产和主表，不做可选润饰、额外构图图或无实际问题的返修演练。复杂格在首批正常生产中验证，必要返修只针对真实严重问题；不单独生图测试返修接口。输入层正式合同尚未变化，不声称前期所有检查已经取消。

## 看图与处理

每个实际返回图只做一次全图快速观察：人物是否明显错认；关键人物、动作对象、剧情信息是否可读。可以把若干原图同时打开，逐格各留一句观察。不逐格放大检查饰品侧别、指形、材质、微表情或像素级画风，不补逐项MEM及六维证据。只有影响剧情判断的局部确实看不清，才局部查看。

普通美观问题、轻微配饰/衣装/画风/背景差异直接留人工。主体可识别、剧情可理解时，轻审核可以PASS且带问题；这不是六项全面精审PASS，问题不得删掉。严重问题写FAIL并做一次有明确目标的修复；修后只再快速看一次关键动作与人物，没有改善则保留较可用版本和真实遗留问题，不追加轮次。仍影响剧情的遗留图标注人工优先处理，不能宣称全部可用。

普通连续性偏差不追查前序全链，不等待整话或跨话全面复审。仅当当前图片显现影响剧情理解的矛盾时，查看必要前图帮助判断。真实生成依赖仍保留，不能用未返回或未知图片当参考。

返回即保存并释放槽位；审核、下一格生成和增量归集沿现有调度独立推进。最终检查源格是否齐全、文件可读、实际采用版本、哈希和容器，不再做一轮全图复审。交付索引和问题表注明轻审核范围。

## 登记入口

使用原 `production_runtime.py --action review --prepare-qa`；轻审核会生成精简模板，队列动作为 `REVIEW_STORY_ONCE`。随后使用原 `review_pipeline.py --state ... --expected-state-sha256 ... --observations ...` 一次保存QA、问题决定、采用和归集。观察文件示例（示例内容不能冒充实际观察）：

```json
{
  "panel_id": "P001",
  "attempt_id": "P001-r1",
  "base_qa": null,
  "qa_template": {"path": "实际模板路径", "sha256": "实际哈希"},
  "reviewer": "实际审核者",
  "reason": "本次实际观察摘要",
  "verdict": "PASS",
  "adopt": true,
  "light_observations": {
    "checks": {
      "identity": {"status": "PASS", "observed": "本图实际人物观察"},
      "story_readability": {"status": "PASS", "observed": "本图实际动作与剧情观察"}
    },
    "issues": []
  }
}
```

普通问题的 `issues` 只填 `location`、`problem`、`target`、`story_critical:false`，工具自动产生留人工决定，不另填六项、问题表和采用引用。有严重问题时标记 `story_critical:true`，对应检查与verdict为FAIL；首轮附原生产决定格式的具体修复方案，仅 `fix_now` 引用严重问题，`opportunistic` 留空。观察引用使用 `/light_review/issues/0` 等。无法修复且选择停止时明确填写停止原因；不得用普通瑕疵触发修复。第二轮工具拒绝继续自动返修。修订使用准确 `base_qa`，原图、旧QA、次数和采用历史保留。

四小时累计有效运行上限、暂停不计时及三小时后继续生产的规则不变；不增加达成率统计。减少审图、取证和返修工作量，不能保证外部生图服务响应速度，也不承诺未经实测的节省百分比。

## 环节限时与自动降级（bounded_stage_fallback_v1）

默认新任务正式入口同时启用本策略。旧包、已冻结轻审核运行没有 `speed_policy` 时不热迁移。用原累计有效运行时钟，明确暂停和等待用户不计时；服务等待计入。单话重试、更换进程、重复打开审核队列不重置已开始的环节预算。不同话仍共用职责总时钟。

| 环节 | 有效时间阈值 | 工具实际降级行为 |
|---|---:|---|
| 前期可选细化 | 职责开始后45分钟 | `optional:true` 或 `--optional` 的可选派生/重复复核直接返回 OPTIONAL_WORK_SKIPPED，继续必需工作，不等待用户放行 |
| 接包可选整理 | 生产职责开始后10分钟 | 同上；不再重排已核验包、做可选重排版。首次必要审计及缺件检查保留 |
| 编译工具compile | 本话首次compile起90秒 | 在合作检查点中止整批只读编译，之后每次最多5格；其余格号在 next_compile_panel_ids 中，必须继续处理，不冒充全批完成 |
| 单图看图/登记 | 本格首次准备QA起30秒 | 改为一句实际观察；若已提供两项真实观察，自动合为单条，不要求重填。仍不能用空观察自动PASS |
| 单格返修规划 | 本格首次准备QA起8分钟，或总预算剩余≤30分钟 | QA保存或返修授权入口自动改为采用已有图片、问题留人工；保留原图、失败和QA修订历史，不创建新尝试。明确保留用户亲审的事项不代签 |
| 打包 | 打包开始后30秒 | 初始用低压缩；到时剩余成员改为ZIP存储，不回头重压已写文件。成品图片原字节始终保留 |

先把所有独立就绪格的首轮图片出齐，再处理可用预算内的返修；不要因为一格想做得更好拖住整批。新的返修授权在落盘前再检查一次时限，已提交请求仍须收图留证，不能超时重发或假装未调用。三小时不是停止首轮生图的门槛，四小时硬限不变。

前期/接包开始及准备继续润饰时，通过 `workflow_session.py` 的请求 `{"action":"stage-check","state":"实际状态路径","phase":"preparation"}` 或 `phase:"intake"` 查看实际预算。需要跳过的可选工作必须在工具入口标记 `optional:true`；使用production_runtime直接派生时加 `--optional`。收到 OPTIONAL_WORK_SKIPPED 后直接进入下个必需环节，不换入口重做可选项。脚本审计、必需资产、真实格数、实际返回保存、授权及完整交付不能标记为可选。仅凭时间不将缺少的材料伪造为通过。

看图超时后，原qa-save请求的light_observations改用：

```json
{"single_observation":"实际看图后：人物是否正确、关键动作及剧情是否可读的一句结论","issues":[]}
```

verdict仍是实际PASS/FAIL；有普通瑕疵就在issues保留，严重遗留标注人工优先处理。已确认严重问题过返修规划窗口时自动接受“有遗留的成品材料”，不会宣称全部图片视觉合格。无真实图、坏文件、源格缺失不计为完成。

这些时间约束作用于已接线的工具入口与合作检查点。模型在工具外的思考、磁盘底层阻塞和外部生图服务不能被本工具强行加速或同步取消；长服务等待时继续其他独立就绪格，不靠重复提交碰运气。前期必需输入验证、单个5格编译分片的必要校验仍须完成，阈值不是所有步骤的物理强杀定时器。最终只有源格全部有准确去向、正式交付门禁通过后，才交完整成品包。
