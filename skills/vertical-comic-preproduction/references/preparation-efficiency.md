# 第一批前期提速：最小充分设计、代表格与集中收敛

**新任务四小时交包优先**：执行[限时交付合同](runtime-clock.md)。下文整包演练、全部审核/最终D通过才交付、等待所有任务收敛等要求仅保留为旧协议或明确要求完整认证的路径；新任务默认复用已审输入、逐格编译，以全部源格完整交包为完成条件，争取四小时内交齐，七小时有效运行硬停。恢复快照不算完成，不把未审或未完成改成PASS。

适用于新运行的输入审计、A、B、实际包和正式交接。用户委托已覆盖的事项由执行者连续闭环，不新增人工停点。当前RV可采用工作方式；工具接线仅在新冻结版本启用，旧RV恢复时从统一入口导入，保留原始证据。正式生图输入、预算、UNKNOWN和最终接包要求沿原合同。

## 新任务异常审查：普通格不设独立审核工序

新速度优先任务使用 `exception_preparation_v2`。在创作时确定人物、关键动作、景别、真实场景与参考；普通格不再逐格快审、填写三个布尔结论或通读完整prompt。技术检查保留源格、真实引用、已知冲突、背景和执行要求。接触类已有checks自动形成具体处理目标，不新建逐格风险分类表。保留用户指定的批准与实图停点，已知严重问题不能自动抹掉。

```text
python <scripts>/preparation_review.py --state <状态> --finalize --authority <已有准确委托文件> --reviewer <执行者>
```

同次完成普通格技术记录及B/PACKAGE输入采用，不产生人工观察表；没有委托则省略authority，沿用已有适用批准。返回targeted_observations仅列具体风险，普通格已继续完成。对这些格只填写具体处理evidence和issues，再按原observations保存入口登记；不得为凑流程给普通格补审核文字。技术记录为TECHNICALLY_READY、review_performed=false，不是REVIEWED或视觉PASS。前期调用不授予正文生图许可。

局部变更按实际输入与许可分别处理：说明文字变化复用准备结果，相关批准变化只重核对应范围；真实输入或公共约束变化才重做受影响格。新记录的读取证据仍须核验，撤销立即阻止相关调用。原版缓存和冻结包仍按各自合同读取。

## 旧轻审核策略：一次观察、细节留人工

以下一次观察流程用于已冻结的 `essential_preparation_v1`；新策略不重复执行它。


新轻审核任务冻结 `preparation_gate_policy=essential_preparation_v1`。普通格只快看一次：人物是否正确、关键剧情是否可理解、实际输入是否可执行。使用下方入口把同次观察用于镜头就绪与最终输入审核，不再逐格填写设计层六/七项及最终输入九项依据。复杂格在同次观察内核对实际影响剧情的接触、道具或空间风险，不额外开启细节复审。

普通表情、配饰、构图、非关键空间和规则说明问题使用 `EXPRESSION_DETAIL / ACCESSORY_DETAIL / COMPOSITION_DETAIL / NONESSENTIAL_SPACE / RULE_EXPLANATION`，`affects_story=false` 时记录提醒并继续。人物错误、关键事件缺失、剧情相反/无法理解、必要参考缺失和请求不可执行仍阻断相关格。任何配饰/空间问题只要影响剧情，`affects_story=true`，仍阻断。缺格、损坏文件、源稿对应、真实依赖、内容版本与授权保持技术核验；结构不合法的请求不以提醒掩盖。

```text
python <冻结scripts>/preparation_review.py --state <本话状态> --panels P002 P003 --output <新观察模板.json>
python <冻结scripts>/preparation_review.py --state <本话状态> --observations <已填写观察模板.json> --reviewer <实际审核者>
```

模板展示真实输入并自动绑定摘要。审核者只填写各格 `observation`：一段 `evidence`，三个布尔结论 `characters_correct / key_event_readable / input_usable`，以及可为空的 `issues`。问题条目只有 `code / detail / affects_story`；不手填身份、哈希、执行状态、旧九项PASS。命中规则的版本、执行决定和实际prompt约束仍核验，但轻门禁不再重复要求逐规则的reviewer/evidence和逐项PASS；真实用户例外仍按原授权核对。负面观察可保存，但相应格继续HOLD；不能只把布尔结论填真来覆盖严重问题。

已有覆盖准确格号和B/PACKAGE阶段的真实用户委托时，保存命令加 `--authority <运行根内已有委托文件>`，同次保存自动登记两项决定与受影响引用。没有委托时只保存观察，沿用已有有效批准；不能用前期请求冒充正文授权。用户保留亲审项不自动批准。生成新不可变审核文件，旧审核、旧决定、原图和attempt保留；输入变化后拒绝旧观察摘要，只重新查看变化格。只改提醒或说明也不重派生整话。

准备真正等待前图的格使用原静态补齐方案，首次准备模板时用 `--dependency-plan <运行根内相对方案路径>`；前图到齐后用 `--completion` 为变化后的真实参考生成一次观察模板。该观察不能重置初始审核或返修次数。

最终交接将提醒保存在原语义审查文件和实际包摘要内，发布/接收识别同一策略。默认走已有内容闭合发布入口并复用匹配证据，不强制重做解压演练；真实兼容故障、输入变化影响相关证据或用户明确要求时才检查对应范围。完整源格、可用输入与交付容器仍须齐全，候选包不冒充正式交接。

旧冻结运行没有该策略时继续旧合同，不给正在运行的旧状态直接添加字段。修改只用于新运行。

## 输入审计与A：只准备实际必要内容

一次核定全部源格序、必显信息、身份/衣装/配饰状态及实际依赖。普通对话优先复用适用人物/场景/画风，不为每格补姿势板、构图图、独立状态说明或重复资产。脚本明确的新衣装按最新脚本优先委托补最小状态并内部审核；人物身份锚点和配饰自身左右、身体位置、数量、遮挡仍逐格落实。

审计记录指向实际来源和必要差异；同一规则依据集中引用，不在镜头、提示词、审查材料里分别写长篇证明。原稿、格序、真实调用账、有效决定和接包证据保留。所有实际生成prompt仍包含适用具体约束，不能只留下规则编号。

## B：普通格达到标准即停止设计

默认使用[普通格最小镜头模板](../assets/templates/普通格最小镜头模板.md)，仅填写人物、关键动作、景别、必要背景与参考。共同机位和技术字段在shared维护一次，由工具展开；不为每格补美术解说、备选镜头、润色说明。实际人物/动作/背景差异仍须准确，不复制前格剧情。

普通格可复用本场景统一的说话人近景、听者反应、兼容空间的正反打模板。先确定本格事件、出镜人物、状态和必显信息，再选模板；同时反应、接触、道具或画内字要求不能被模板裁掉。复用构图不等于复制表情、动作或人物位置。

完成标准：原稿事件及必显信息完整；人物与状态明确；机位/裁切物理可行；实际输入可执行；没有互斥指令；必要连续性明确。满足后停止换角度、润色和增加参考，不为“看起来更丰富”反复重做。

接触/承托、床或复杂家具、伤臂、武器、镜面、鳄鱼/变身状态、复杂遮挡和配饰左右属于重点，逐格审清具体风险。关键词仅是风险提示，没有关键词不代表已通过普通格审查。新策略普通格不要求独立核对记录，创作时处理必要信息即可。缺少可选站位图或灰阶图本身不阻断。

## 先用代表格走通接口

```text
production_runtime.py --state <状态> --action preparation-plan --write <新计划JSON>
production_runtime.py --state <状态> --action preparation-review --panels <代表格源ID...> --write <新代表格合并材料JSON>
production_runtime.py --state <状态> --action preparation-review --write <新全话合并材料JSON> --package-write <原格式实际包JSON>
```

plan只读实际源快照和已有镜头，优先选择能覆盖不同风险的少量格，再补一个无已发现风险的格。执行者实际阅读后可补充漏检风险或调整样本；不是随机固定前三格，不为凑样本额外设计复杂格。保留完整源序和已有全局合同的基本结构，先准备样本的实际输入及语义核对；其他格可记录真实未完成，不伪造PASS。不要求先把普通格精修完成才开始样本。

preparation-review复用完整候选包入口的公共检查和逐格技术检查，样本模式只构造所选格的实际包签名。原全局条件仍检查；缺口只生成准确范围，不因样本成功宣称整话通过。发现相同字段、裁切枚举、参考归属等共因，由总控统一修接口/模板后继续，不让各话重复发明兼容格式。全话仍须完成最终真实检查。

## 一份实际输入、两项决定

新入口在同一读取事务内形成generation_review_package_v1，并从同一版本镜头派生shot_design展示，合并保存在combined_preparation_review_v1。generation_package是原格式的完整嵌套对象，含实际prompt、参考顺序/哈希及规格；不是另写一套提示词。这个合并材料不是新的批准格式：用--package-write同时保存嵌套generation_package原对象为原门禁认可的包文件，不重跑编译、不修改对象；B仍绑定真实镜头/审计。实际审查后分别登记shot_design和generation_package决定，不将合并JSON冒充已批准生图包。

若已有同版bundle材料，直接展示并登记，不为换展示格式重新编译。当前入口不提供跨命令持久PASS缓存；新输入需要核对实际变化。输入读取事务结束且依赖复核完成之后才保存新材料。不要边读边重写被冻结依赖。

## 检查结果与处理动作分开

issue_disposition.py输出工作建议，保留原validator错误与PASS/HOLD。四种动作：

- RECORD_CONTINUE：明确的可选机位探索、无必要prompt润色、重复说明、可选额外参考；停止润饰并继续。
- AUTO_REPAIR：可核实路径重绑、已知权威输入的派生字段同步；执行者在现有授权内立即修复工作材料，再重检相关输入，不问“是否修复”。修好前只阻止该格实际提交。
- LOCAL_BLOCK：真实身份/动作/必要参考/连续性未解决等，处理该格及原门禁识别的真实依赖，继续其他可独立工作。不是停整个任务，也不是自动要求人工裁决。
- GLOBAL_BLOCK：全局来源/格序/权限/共同证据不成立时先修共同依据；只作用于原门禁确定的范围，不把每话错误扩大成跨话全批错误。

普通建议存为镜头可选planning_notes，条目为code与detail。例如`{"code":"OPTIONAL_PROMPT_POLISH","detail":"现有prompt已充分，不再润色"}`。仅允许的普通建议代码不产生HOLD；未知/格式错误的代码局部诊断。不要把实际技术错误改名为OPTIONAL来放行。真实问题仍放原错误/hold记录，不搬入普通建议。planning_notes不改变创作签名；与实际画面相关的修改必须更新权威创作字段。

这些工作建议不授予生产权限，不解除原hold、不放宽预算或取消实际依赖。普通问题自动修复；最终输入缺口仍要闭合。相同问题第二次出现先修共因，不重复生成一轮报告。不为处理警告另加人工确认或进度门禁。

## 连续收敛到正式交接

制作中按变化与实际依赖处理，避免反复执行整话命令或复制整个RV。普通文案修饰、报告排版和未变素材不启动完整重审；实际prompt、参考、参数变化则重审真实影响范围。B/PACKAGE在用户有效委托内内部审查，不写“供你审核”。

共因闭合后集中完成最终全范围输入检查，复用内容导出证据按原发布合同形成正式ZIP；仅用户要求或真实兼容故障才做解压、路径绑定及门禁演练。结果未变且已有匹配证据时复用，不因汇报进度重跑。修复改变接包依据时重做相应演练，不把“只跑一次”当成跳过修复验证的理由。第一批不修改原最终门禁，不把候选PASS、warning或协调进度当成最终交付。


第二批工具与工作流程已接线，见[唯一主表与增量派生](draft-authoring.md)。新运行在代表格接口打通后转入单一主表，不继续手工并行维护三份创作输入。
