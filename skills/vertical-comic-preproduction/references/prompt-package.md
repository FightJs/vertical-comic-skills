# B阶段逐格提示词写法

新运行的主表、增量派生、共用规则/图集复用与少冻结执行见[第二批草稿提速](draft-authoring.md)。派生文件不授予批准或生产权限。

## 正文顺序

写正文前按 [identity-confirmation.md](identity-confirmation.md) 核对全部源称呼、明确身份/人物关系、本话外观及场景状态和批准资产。任一关键疑点先暂停询问，不用模糊提示词掩盖。通过后将编译的 `身份与状态锁定` 块写进真实 `prompt.txt`，同步索引与逐格 JSON；画外人物仅保留身份记录，不写成需要生成的人物。

建议每格用以下顺序，去掉理论解释，但不要省略会改变画面的事实：

1. 镜头与明确裁切、机位/景别/比例及可见区域；
2. 人物身份及当前衣装/可见首饰状态，主体屏幕位置；
3. 指定表情、身体方向、视线和动作阶段；
4. 必须可见的接触、承托、物件与真实遮挡；
5. 本格背景模式、批准场景色调/光向、保留项与省略项；
6. 人物和动作对象的重点清晰区域、批准画风；
7. 按实际数组编号的参考职责。源稿原文保存在locked_script，不混入与执行方案矛盾的旧构图句。

正文须包含明确身体裁切与背景层级。只描述本格可见内容，画外人物/道具保留在连续性资料中。全身角色参考用于身份，宽景参考用于空间，均不要求把参考图全貌画进每格。半身必须仍容纳必要手势、接触点、物件、画内文字和同时反应；选择标准见 [shot-framing.md](shot-framing.md)。

相邻信息放在审计记录中；生图正文执行本格已批准镜头，不写“必须换景别”或泛化的“禁止同上一格景别”。

启用 `reference_continuity_v1` 时，正文内容块后加入由 `reference_bindings` 编译的 `参考用途绑定` 块，明确每个别名属于谁、只迁移哪些内容、不迁移哪些内容。字段、编译函数与边界见 [reference-continuity.md](reference-continuity.md)。仅列别名不能代替用途；不要把画外连续性记录作为需要生成的角色内容写入正文。

Codex 分支的图像职责和实际工具参数见 [codex-imagegen.md](codex-imagegen.md)。`机位强制执行` 是兼容的指令块名称，不代表已执行硬约束。仅写文件名或别名不会上传图片；用实际参考数组顺序编译图片编号和用途。

## 推荐示例

以下只展示内容与参考职责写法，完整交付仍须包含前述机位、内容、身份与用途块。两种辅助图由 D 阶段按需选择，样式见 [visual-continuity.md](visual-continuity.md)。仅引用真实采用的图片，图片编号由实际数组编译；不要给无需构图图的格保留 @COMP 空槽。

### D 阶段采用灰阶构图参考

```text
竖版中近景。画面左侧是背对观众的男主后肩和大部分后脑勺，只露出少量画右侧面部；画面中央偏右是面对观众的女主上半身。女主身体朝画面左侧，视线落向男主，眉头轻收，嘴角压住惊讶。前景桌沿遮住两人的下半身。画面右后方保持原场景的窗，画面中央后方保持固定书柜，不能移动门窗和道具。自然柔和日光从场景左前上方照入，阴影方向保持一致。参考图1 @COMP_P012：framing 提供构图和裁切，spatial_layout 提供位置、前后层级和遮挡；实际动作、表情和视线执行本格记录，不迁移示例人物身份和衣装。参考图2 @客厅东南视图提供空间、材质与光照；参考图3 @女主立绘提供女主身份和当前衣装；参考图4 @男主背面资产提供男主身份和当前衣装。以上图片须实际传入工具。
```

### D 阶段无需额外构图参考

```text
竖版肩部以上近景。摄影机位于批准客厅机位 CAM013，人物眼部高度、正面偏画右，女主位于画面中央，身体和头朝摄影机，视线落向画面左外的说话者，嘴唇轻抿，表情依本格已锁定反应。画面下缘裁在胸口以上，双手和杯子不入画；右后景仅露出该机位可见的固定窗框，保留背景轮廓清晰、简洁；通过取景减少背景面积，不加入背景虚化、散景或光斑。参考图1 @客厅CAM013视图提供批准空间、材质与光向；参考图2 @女主当前状态提供身份及本格可见衣领。两张参考的全景、全身和原姿态不扩大本格裁切，不加入画外说话者。
```

仅当本格剧本确实无需入画双手/杯子，且现有机位证据覆盖这些可见关系时采用该方案，在逐格记录写 composition_reference.mode=NOT_REQUIRED 及简短依据。人物名、机位、动作和背景均替换为本格真实值；无需新增灰阶稿、站位图片或构图审阅文件，空间与裁切仍须核对。

## 禁止写法

- “自由机位”“任意角度”“自行发挥”；
- “参考附件”“按之前一样”但没有实际别名和文件；
- 只写“人物在左边”，不说明是画面左；
- 只写“侧脸”，不说明实际脸部可见比例；
- 为了展示完整人物而删除遮挡；
- 把对白、心声和后期SFX混进需要随图生成的场景文字；
- 用长篇摄影理论替代画面内容。
- 用“半身照”替代具体裁切，或为了容纳完整参考板补出腿脚、整个房间和画外人物。

## 负面提示词重点

Codex 没有独立负向词参数：将本格必要避免事项合并进最终 `prompt.txt` 和同步的 JSON `prompt`，不要向工具传 `negative_prompt`。兼容负向文件可保留为资料。

根据本格需要加入：背景结构漂移、门窗位置改变、道具位置改变、错误反打背景、错误人物朝向、完整正脸替代后脑勺、解除真实遮挡、发饰/伤势换侧、违背脚本或批准方案机械复制表情/动作、画面左/右位置颠倒、场景光向改变。

## 按画面条件选用的通用提示词模块

以下为提取后归纳的方法，不是经验证成功的原始调用。每格填入批准事实，只选适用模块，合并现有机位/内容/身份/参考块，同一事实只写一次。示例不作为其他剧情的默认值；固定画风词替换为本书批准画风。通用判据引用实际MEM，本书具体状态留生产包。

### 主体与边界

输入framing.focus/body_crop/required_visible及visible_region，写上/下缘、主体画面位置、身体露出范围和必显动作。近景优先，不设固定主体占比。示例结构：人物在画面[位置]，上缘[范围]、下缘[范围]；[表情/动作]为重点，[必要对象及接触点]完整入画。全身参考不扩大本格裁切。

### 按叙事选择背景

新narrative_background_v1按[背景模式](background-treatment.md)选择clear_limited、scene_flat、scene_softened或scene_outline；特殊获批景深沿用approved_depth_of_field。近景优先采用实景柔化，保留可辨识的场景大轮廓，先保证必显剧情与物理关系，不设配额。旧策略保留原clear_limited执行。

实际用visual_evidence.framing_execution_block编译，已在visual_execution_block中不重复追加。指定场景底色/光向、必要锚点、具体省略项与重点清晰对象；宽景参考不要求完整迁移全套家具和灯具。平涂不是散景或低清，空间事实不被省略。具体字段、反例及验收见共享模式文档。

### 手、物件与接触

可见手/肢体执行MEM-006，多人接触另执行MEM-002。写角色自身左右手、指掌如何围绕对象、拇指对握、腕部接续哪条前臂、接触部位及当前动作阶段/结果。
示例结构：角色自身[左/右]手握[对象]，[可见指掌]与[部位]接触，拇指对握，腕部自然接续[所属前臂]；当前处于[批准动作阶段]。
contact的actor/actor_limb/target/target_part/visible_path进入正文。真实遮挡不强求五指全露。角度让关键接触不可读时先修候选机位，不重复“手指完美”。

### 连续动作与视线

执行MEM-003/005及适用前序状态。分别写世界位置、屏幕位置、头部方向和视线目标；目标在画外不代表要补入人物。明确持物手、支撑手、被接触部位和动作阶段，变化有源稿或准确批准依据。摄影机反打可改画面左右，不能交换真实站位。

以下句式只填当前批准事实，放进已有checks.expected/人物描述，不整表复制进每格：

| 实际条件 | 可执行句式 |
|---|---|
| 多手或递接 | [人物]自身[左/右]手当前负责[任务]，接续[所属前臂]；[物件]现由[承重者]持稳，[另一手]处于[接近/接触/接稳]。不在原掌/腕/袖口旁补出第二套结构。 |
| 自然持物 | [手]在[身体附近位置]握住[部位]，肘腕随[用途]自然弯曲；[物件]与手/头保持批准比例，突出对象依靠裁切，不强行朝观众举出。 |
| 全身或承托 | 肩、髋、膝、脚朝向形成可行姿态；[身体部位]由[既有表面]承托，[脚]位于[落点/画外]，[覆盖物]仅覆盖[部位]。 |
| 持续在场 | [实体]仍处于[世界位置]，本机位[露出具体部位/被具体实体挡住/位于哪条画幅边界外]；不因当前无台词而离场。 |
| 视线与正反面 | 摄影机在[位置/高度]，头朝[方向]，眼神落向[目标]；[物件]正面朝[使用者]，摄影机只能看到[背/侧/正面]。必要读屏通过可行机位实现。 |
| 真实遮挡与清晰度 | [遮挡物]覆盖[明确部位]，剩余露出的[眼部/指掌/连接]须结构可辨；不以头发、阴影或模糊填掉没有被遮住的结构。 |

抽象信息流、示意箭头、无线图标属于表现选择，不自动变成物理连线。正文仅执行本格批准的真实动作或图形表现；如果无需画内显示内容，使用物件背面即可，不能为了说明信息改变物件朝向。

### 可见首饰与范围内返修

首饰只编译当前可见且有清晰依据的结构、层数、连接、佩戴侧/手指，实际引用参考仍最多五路径；同色不等于同款，按MEM-005核对。
返修执行MEM-004：仅修[实际缺陷及区域]至[可观察结构]；保留[正确脸型/发型/衣装/首饰/动作/背景及既有修正]。底图选本格真实清晰返回图，错误要素不能当成应迁移特征。返回后核对修复与未授权变化，“修改版”文件名不证明通过。

### 编译前去冲突

清理相反旧指令：肩上裁切却要求全身、清晰背景却要求强散景、保留关键手势却要求双手出画。锁定原文留locked_script，不把矛盾旧描述贴回执行正文。机器只查字段、文本块与引用一致性；语义冲突仍需执行者审查。来源案例的服装替代版本不能当成忠实修复模板，源动作/衣装不适用时须另行解决。

同次核对一只手是否同时承担互斥任务、脚向与躯干是否扭断、使用者是否在看物件背面、俯拍是否错误转成仰头。不得用增加“自然、正确、高清”等形容词代替明确动作关系。结构返修沿remove/replace/connect写清旧结构删除、新结构替换及连接，保留区域另列；返图须重数整体结构。

## 必要输入完整编译一次

execution_quality_v1使用build_prompt的具体内容分支：具体裁切、可见内容、动作、场景及饰品由visual_execution_block统一编译，人物描述和实际参考用途随后补齐。不要再次附加同义的可见范围、必显清单或整套通用禁令。签名、预算、审批和历史轮次留JSON/审计，不作为绘图命令。原始locked_script继续独立保存。

缺失角度/景别的旧包默认值只是待审候选，不证明已有镜头依据；参考编号必须按最终真实数组重编译。模型不提供的seed/权重/区域锁定等不能在prompt或报告中虚构。

最终实际请求编译完再按[最终输入审查](final-input-semantics.md)逐格核对，不能只审镜头初稿。身份/衣装资产不提供本格默认表情；通用模块不得覆盖源稿明确的睁眼、微张嘴、失焦或可见范围。修正权威记录后同步生成prompt.txt、逐格JSON、全话包及判据，禁止只替换一处旧文字。

必要约束可充分展开，不设置绘图描述长度目标。repair_prompt_package_v2.compact默认只整理空白与结构，不截断长动作、裁切或配饰文字；显式摘要用途才可传长度限制。build_prompt保留明确机位、景别、比例与具体视觉块，并将原generation应用中的本格prompt_constraints去重补入正文。原始规则全文和审批/预算信息留审计。

最终输入按[前期收敛v2](final-input-semantics.md#前期收敛按包执行v2)审实际发送全文。人工写的包同样须带齐具体约束；“编译过”不能代替实际审查。
