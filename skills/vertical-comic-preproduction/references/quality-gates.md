# 质量门禁

当前新任务先完成整话资产/A、镜头/B、语义核对、比例和生图包批准，再按 [整话异步生产](episode-async.md) 对已就绪格持续生成、返图即做六项QA，必要时滚动返修，最后完成整话连续性与D。局部暂停与未变QA复用仍适用。旧半话、batch5或单格RV按原冻结合同恢复。

> 阶段化五件套执行时，同时遵守 [固定流程](staged-workflow.md) 和 [生图输入输出合同](generation-io.md)。每次生成及返修必须实际传入批准画风样例，单独审查画风；最终交付逐格图片包，旧“进入排版/C阶段”只作历史术语，不启动排版。单格原编号快照由 staged_workflow.py 调用完整门禁校验，不能为通过旧完整话编号检查重编号。


## 身份、外观和场景确认门禁

- 按 [identity-confirmation.md](identity-confirmation.md) 先核对源称呼→明确角色名称/唯一 ID→称呼与人物关系→本话外观状态→批准资产。尤其“傅妈”等亲属称呼，必须确认对应人物与关系对象，不按姓氏或年龄猜脸、服装。
- 身份确认不替代服装/伤势/时期状态确认；场景同名不替代地点归属和状态确认。绑定须有匹配本书、本话/格子范围的真实确认依据，已有适用依据可复用。
- 缺失、矛盾或范围不明分别标记 `IDENTITY_HOLD`、`APPEARANCE_HOLD`、`SCENE_IDENTITY_HOLD`，列出原称呼、依据、冲突、受影响格子和需用户决定的字段，暂停询问；回复前只做不依赖未决项的读取/整理，停止对应设计、补图、站位和提示词生成。
- 未决项不能随阶段流转、修复或旧包升级被删除；新外观/地点变化重新打开相应确认点。一次出镜仅豁免独立资产，不豁免身份、状态或人物关系确认。
- `validate_preproduction.py` 同时核对身份合同、实际资产哈希、镜头表/索引/逐格 JSON/实际正文同步；结构 PASS 不证明证据内容确有批准，也不证明像素正确，仍须实际读依据、看参考图与返回图。

## 镜头门禁

- 以本格必要信息选择最小充分取景；对话优先中近景、半身和特写，全身/宽景必须记录具体必要信息；
- 相邻变化引用本批冻结MEM-010版本：v2按叙事与物理连续性允许同景别正反打，v1保留原合同；只改签名无效；
- 没有无理由重复正反打；
- 反打后的脸部可见比例符合物理位置；
- 背景随相机位置正确变化；
- 画面比例服务叙事，默认竖屏优先但不锁单一比例；
- 机位候选没有被误标为已批准。
- 新记录的 `framing` 明确焦点、必显信息、身体裁切、裁切理由、背景层级；半身不裁掉必要手势、接触点、道具、画内文字或同时反应。

## 脚本锁定门禁

- 原脚本的格号、顺序、对白、独白、旁白、SFX文字和事件逐字保留；
- 镜头改编只改变画面呈现，不改变剧情事实、人物关系、动作结果或读序；
- 目标—阻碍—结果只是对已有文本的视觉分析；
- 未被脚本支持的心理、动作、道具和剧情转折不得被添加；
- 发现需要改词、删格、并格、改事件或改说话人时，必须 `SCRIPT_CONFLICT`/`SCRIPT_LOCK_HOLD`。

## 连续性门禁

- D 阶段逐格空间与裁切核对必须完成；站位图、目标机位灰阶构图参考图分别按需选择。现有证据充分可不做，已有适用图优先复用，缺少未选用的图不构成 HOLD；未知空间关系仍 HOLD。启用条件和图片标准见 [visual-continuity.md](visual-continuity.md)；
- 每个角色的身体、头部、视线、表情、手部动作均有逐格记录；
- 相邻动作服从源稿；脸部可比较时执行 MEM-007 的当前微表情判据，画外/遮挡范围按批准裁切核对；
- 角色自身左右侧的发饰、伤势和标志物没有交换；
- 固定道具和场景锚点坐标没有漂移；
- 遮挡、接触和前后层级符合物理关系。

## 资产门禁

- 重复出镜对象有来源或明确 `MISSING`；仅一次出镜的人物/场景/道具不要求单独资产，以出镜统计和具体描述登记豁免；
- 九宫格结构、比例尺、光照和材质一致；
- 补资产未被误称为批准资产；
- 每格实际参考图已经复制到本格目录并有哈希；生图引用必须可解码为位图。SVG/JSON放审计资料，需要时将真实矢量站位图导出PNG；JSON与文字不转成参考图片。

## 提示词门禁

- 每格有镜头、站位状态记录、可见区域和 camera signature；站位状态 ID 不要求对应一张图片；
- `prompt.txt` 本文必须逐字写出机位角度、景别、画幅比例、摄影机位置/朝向和可见面/遮挡逻辑；只在 JSON 中登记 camera signature 不算通过；
- `camera_angle_family`、`shot_scale`、`frame_ratio` 和 `camera_execution_block` 必须同时存在于每格 manifest，并与 prompt 正文一致；
- 每格正文还必须有 `画面内容锁定` 块：场景、实际可见区域、人物画面位置/身体与头部朝向/视线/微表情/动作、固定道具与背景锚点、前中后景和遮挡关系；不能只写“参考资产”或只列 @ 文件名；
- 不设置600字等字数门槛；以具体位置、可见面、动作表情、背景与遮挡的完整性核验，不用重复原文凑字。
- 每格提示词使用画面整体坐标；
- 每格正文逐一引用所有真实参考别名；
- 没有“自由机位”等模糊表达；
- 背景和遮挡足够具体；
- 提示词应去掉生产理论，但“简洁”不等于省略画面事实；凡是会影响画面内容、位置、状态和连续性的事实必须写进正文。

## HOLD 不能伪装成 PASS

- `CAMERA_HOLD`、`HOLD_NOT_YET_SPATIALLY_PROVEN` 和“因缺空间证据产生的 CAMERA_EXCEPTION”不能转为 `PASS`；
- `CAMERA_EXCEPTION` 必须记录重复理由及实际格对确认，否则仍HOLD；适用规则更严格时还须核对其原范围例外和替代判据，不能用旧模板豁免；
- 资产补齐、关系图完成或提示词写完，不等于摄影机物理可见性已验证；
- B 返回底图后，实际图片比例、相邻机位、相邻景别和背景锚点必须重新审查；结构检查 PASS 不代表底图通过。

## 返回底图门禁

- 按已确认 ID、外观状态及场景状态对照实际图片；首次入画、新服装/伤势、跨场景后重现重点复核。错脸、错衣服、错关系对象或错场景保持 `IMAGE_CONTINUITY_HOLD`，阻止排版。
- 生成图的实际像素比例必须符合逐格 `frame_ratio`；
- batch5_v1 的源首五格（不足则全部）须并排审查并获 C 批准；每批另做批内与跨批连续性检查。未声明模式的旧任务保留 P001–P003 三格审查；
- 按批准镜头及当前命中规则核对实际焦点、裁切、可见信息和相邻变化；规则要求未满足、意外复制默认视图或无批准的完全重复构图时保持 HOLD；
- 半身/局部被补成全身或宽景、补入画外人物、遗漏必要动作/道具/文字时继续 HOLD；背景与身体裁切正确性须视觉复核；
- 任何 `IMAGE_CAMERA_HOLD` 都会阻止进入排版；动作变化不能被谎称为相机变化，须按批准的反应或持镜理由审查。

任何门禁不通过都输出 HOLD 和失败层级，停止受其影响的下游工作；batch5_v1 当前批次已发出的独立请求可保存返回候选，但不能越过整批门禁。共用基准失败暂停受影响各话，其他无依赖且已授权的话可继续。

## 第一轮参考与分项门禁

启用 `reference_continuity_v1` 时按 [reference-continuity.md](reference-continuity.md) 检查参考用途/人物归属、合同与批准构图一致性、跨格身份/衣装状态和五项预定验收范围。缺姿态参考不一律失败。返回图必审维度保持 UNREVIEWED 直至实际看图；任一必审维度 FAIL/未审/缺证据均继续 HOLD。画外豁免不能删除必显信息；同场景换机位允许正确的背景投影变化。分项记录检查成功不授权排版，仍须既有整体视觉审查与批准。


## Codex 参考输入与对照验收

按 [codex-imagegen.md](codex-imagegen.md) 核对实际图片文件、数组顺序/角色归属。CREATE/REUSE 另核对干净构图证据与批准机位/裁切/比例一致性；NOT_REQUIRED 无需构图图片、别名或核对文件。标注俯视图只作审阅。别名存在不能证明图片已提交；COMPLETED 必须有可观察调用和返回证据。返回图按交付容差检查真实像素比例，有构图图时并排检查接触点、遮挡、背景投影，无图时依据批准镜头、空间记录与资产审查；仅图片对照为 NOT_APPLICABLE，五维未审/失败继续 HOLD。新构图图不替代身份、剧本、空间和既有批准门禁。
