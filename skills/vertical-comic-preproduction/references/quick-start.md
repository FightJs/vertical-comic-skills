# 首次使用与短启动入口

**新任务四小时交包优先**：执行[限时交付合同](runtime-clock.md)。下文整包演练、全部审核/最终D通过才交付、等待所有任务收敛等要求仅保留为旧协议或明确要求完整认证的路径；新任务默认复用已审输入、逐格编译，以全部源格完整且四小时内交包作为唯一成功条件。恢复快照不算完成，不把未审或未完成改成PASS。

## 接包生产：免外部配置

用户已提供正式ZIP或完整解压包根目录时，先执行本节，跳过首次书籍配置。只接包用途的使用者不需要本书profile、外部脚本文件或资产目录，也不需要重新选择书名/话号。没有包路径时只补问本机包路径；可选输出位置未提供则使用receive默认值，不为此新增确认。

```text
使用条漫Skill接包生产：【本机正式ZIP或完整解压目录】。
依据包内材料完成指定范围生产，输出位置：【可选，不填则默认】。
```

安装版comic_start.py receive接收ZIP用--zip，解压目录用--package-root，输出位置用可选--output。不进入prepare、read_config或脚本/资产配置流程。安装ZIP用于安装Skill，与正式漫画交接ZIP区分；不能把案例导出包或缺素材的文本摘录当正式生产包。

书话范围从校验后的交接索引读取。receive返回input_mode=package_only_production、external_inputs_required=false、book_profile_required=false，以及bound_run_root、run_index、production_entrypoints。每个入口给出本机state、runtime_script和frozen_scripts；按这些入口及包内实际模式继续，不拼接前期电脑路径。

包内源稿/执行源快照、必要参考、实际prompt、输出规格、规则/冻结工具、审查和历史预算作为依据；不要求接收者另提供整份剧本或完整资产库。状态中的usage_config_path仅保留前期来源信息，不重新加载。运行环境按本机Python及依赖准备；生产授权和可用图像工具另按真实指令核定，接收成功不代表已经生图。

缺件或不兼容时先列准确包内文件/格范围并处理；不把“重新配置脚本和全面资产”当默认补救。收到包后复用未变审查，不重新做A/B、代表格设计或主表迁移。包内真实依赖和有效审核节点仍按该包合同及后续适用授权执行。


前期询问策略先按[明确委托的最少询问规则](grouped-review.md#前期仅询问无法消解的剧本资产冲突)判断；适用时，本页前期亲审/确认均改为执行者实际审查和委托决定，导出沿条件授权执行，不增加人工停点。生产阶段及旧冻结合同不因此改变。

对用户只展示总控入口，不要求粘贴内部policy/门禁/规则说明。规则库随五件套安装在总控assets/rule-memory；无需第三个路径或GitHub账号。前期新项目只需脚本、资产和话号；书名不明确时集中核对一次，不能猜格数或把候选当批准。

## 执行环境

首次运行或解释器变化时，读取本机CODEX_HOME/skill-bundles/vertical-comic-skills/installed.json中记录的python路径；有效时用它运行脚本。没有安装记录时选择实际Python 3.12+，先运行scripts/runtime_environment.py。Windows无需WSL；不要尝试pip安装fcntl。所有CLI使用UTF-8输出，路径作为独立参数传入，不拼接shell命令。PowerShell调用含空格的解释器时使用`& "解释器路径"`。

prepare与receive会在创建RV前检查当前环境。实际生图能力另按当前工具定义核验。安装成功、运行检查通过、真实生图可用是三个不同结论。跨电脑只复用包内冻结内容，不复用来源电脑的Python或绝对路径。旧冻结包不支持Windows时，当前生图人员保留冻结包，在包外建立迁移候选并直接询问用户确认受影响范围；不在接收端热修冻结包。

依赖清单随Skill及新冻结快照携带于assets/templates/runtime-requirements.txt；环境报告返回实际清单路径。接收端缺依赖时用本机已选择的Python执行`-m pip install -r <清单路径>`，再重新检查，不依赖前期电脑的虚拟环境目录。

## 安装后的首次配置引导

用户明确要前期制作且说“第一次使用”“帮我配置”或缺少完整前期输入时，进入本节。已有交接包时优先执行上方免外部配置接包，不进入本节。不要要求用户先创建或找到“条漫Skill使用配置.json”，不要把长启动词或技术JSON交给用户填写。

1. 先按用户已提供的信息判定职责。接包生产直接进入免外部配置接包；前期制作才检查当前项目`.comic/books`中的本书配置。尚不明确时只问一次选“前期制作”还是“接包生产”。只补问缺项，不让已配置用户重新走首次流程。
2. 前期制作将缺少的信息合成一条清晰请求，允许用户拖入文件/目录或提供实际路径：书名、源脚本文件、该书资产目录、准确话号。话号可写E021–E025。书名只有可从可靠元数据明确识别时才预填并展示；不从模糊文件名猜作品或格数。
3. 用户可直接回复路径，不需要选择技术policy、规则库、并发合同或输出RV。项目使用当前已明确的工作目录，默认输出及内置规则自动设置；用户可选填输出位置和执行agent数量。没有项目上下文或存在多个可能的项目目录时集中核对，不能写到猜测的目录。
4. 自动把用户路径解析为本机绝对路径，检查脚本确为可读文件、资产确为可访问目录；错误只询问对应项，不创建假文件或继续使用占位符。接到其他机器的路径时说明需要本机路径，不机械拼接。真实脚本话号/格数仍由后续源审计核对。
5. 信息齐全后调用comic_start.py prepare自动生成本书profile、本次配置、新RV及冻结快照，只展示一张输入/保存位置摘要并继续原准备流程。普通路径摘要不增加一次确认；与既有本书路径冲突等真实差异才集中询问。配置生成不代表A/B或正文获批。
6. 接包生产接受正式ZIP路径或已解压包根目录；新版单ZIP的内置清单和正式发布证据由程序校验、书话从包内读取，审核人按用户明确要求记录。包不完整或不兼容时报告具体缺项，不要求填写源脚本/资产/技术JSON。

前期缺项时可这样询问：

```text
我来自动完成首次配置。请提供以下缺少的信息：
书名：
源脚本：拖入文件或提供路径
本书资产：拖入文件夹或提供路径
话号：例如E021–E025
其他设置先用默认值；如需指定输出位置或agent数量，可以一起说明。
```

用户首次启动只需：

```text
使用 $vertical-comic-preproduction。
第一次使用，请引导我配置，进行前期制作。
```

配置成功后告知“本书路径已保存，以后只需书名和本次话号”，同时给出本次实际profile和运行目录，不声称已完成剧本审计或图片验收。首次制作无需登录GitHub、选择规则同步或开启自动上传；那些只在用户明确维护规则并选择同步时处理。

## 前期端

先按[任务来源](task-origin.md)区分独立制作与恢复。prepare只创建新任务，已明确重新制作不因旧工程存在而改走续做。使用保存的书配置只复用脚本/资产路径及偏好，不继承旧成图或返修账；可选request-source保存真实用户原话，不增加用户技术填写步骤。

首次：

```text
使用 $vertical-comic-preproduction，进行前期制作。
书名：【书名】
脚本：【脚本路径】
资产：【资产目录】
话号：E026–E030。
输出位置：【本机输出目录】
其余使用默认配置，完成后只交一个正式交接包.zip，交接说明与校验清单内置。
```

已有本书配置后：

```text
使用 $vertical-comic-preproduction。
前期制作：【书名】E031–E035，使用本书配置。
```

执行者把自然语言映射到`scripts/comic_start.py prepare --project <当前项目> --book <书名> --episodes E026–E030 --script <首次路径> --assets <首次路径>`；无需用户学习CLI。profile存项目`.comic/books`，本次话号保存在新RV任务配置，不写回本书默认话号。默认输出为项目/条漫输出/书名/首末话号/全新RV，输出路径或worker数量可由用户临时覆盖。初始化只建未批准模板与唯一运行快照，之后必须核对真实源稿格数/格序并正常推进A/B；不调用正文生图。

同书已配置路径与用户新路径不同则集中核对，不静默覆盖；旧comic_usage_v1显式memory_root继续读原库，不升级正在运行RV。新简易入口使用内置+用户增补；维护完成后只影响新运行。原A、最终B/包、高风险/D及条件ZIP导出批准按当前任务模式执行。

## 接包端

```text
使用 $vertical-comic-preproduction。
接包生产：【正式ZIP路径或已解压包根目录】。
输出位置：【本机输出目录】
审核人是我，其余按包内流程执行。
```

执行者使用安装版`comic_start.py`：ZIP调用`receive --zip <正式ZIP>`，提前解压的目录调用`receive --package-root <包根目录>`。目录根包含`ZIP文件清单.json`和`交接验收索引.json`；若用户给外层解压目录，先定位唯一包含两者的直接子目录，多个独立交付集合才询问选哪一个，同一集合的连续分卷直接汇集校验。新版默认先形成一个正式ZIP，超限自动连续分包；单包或整套分包内含交接说明、文件哈希清单和演练/导出证据；校验、解压、bind及rehearse按顺序执行。`--output <本机输出目录>`可指定输出位置。默认在ZIP或包根目录旁的接包生产目录建立全新RV。已解压目录只读使用，输出留包外；清单/大小/SHA256和发布证据通过后照常bind/rehearse，不寻找原ZIP、不重压、不重签。目录接收报告注明未核验原ZIP容器CRC，不把这一点当作阻塞。书话范围从包内读取，用户指定子范围时必须核对后建立相应范围任务，不能偷偷截断整个包。新版通过后按整话真实就绪范围进入生产许可；旧包保留原冻结窗口。旧版ZIP仍要求精确同名.zip.sha256；新版无需外部文件，也不套第二层ZIP。缺发布证据或旧包无运行模板时准确报告，不猜替代文件、不伪造绑定批准。

接包后的路径、材料、工具、历史账或设计问题均由当前生图人员在同一任务中集中整理并直接询问用户。获批后只更新和重检受影响范围；不要求用户联系其他负责人、返回另一个会话或重新提交整包。

首次只给用户看一张输入摘要和当前确需处理的差异；审查页合并展示B与包但分别记录决定。extract/bind/rehearse及各项技术PASS留在内部日志，不要求用户逐命令确认。身份、动作、画风、场景及实际图片QA依然由阶段Skill负责。

## 后续更新

安装成功后告诉用户：以后说“检查并更新条漫Skill五件套到最新稳定版”即可，详见[安装更新](installation-update.md)。只在明确要求时查询/更新，不在每格生产时检查网络；无需重复填写本书配置，也无需GitHub登录。


启动与恢复后按[阶段与交付进度](review-progress.md)锁定本次职责、完整指定范围及真实源格分母。前期显示到正式生图交接ZIP，接包生产显示到全范围逐格成品ZIP；短入口返回progress_directory。委托执行者决定不取消对话进度显示。


用户要求累计运行时限时，按[有效运行计时](runtime-clock.md)显式接入；暂停扣时须有真实事件依据，安装Hook不等于已获宿主信任。


微信发送交接包时执行[无损去重与分卷运输](handoff-transport.md)：正式发布后导出，完整恢复验证后发送全部交付文件；接收入口自动识别。


用户要求4小时累计运行时限时，执行者传--runtime-limit-seconds 14400；启动入口自动核对Hook身份并绑定，无需向使用者索要session_id。接线缺失按runtime-clock.md修复，不能省略计时参数后宣称限时已启用。

接包简用：全部连续分卷下载到同一文件夹，将第001卷拖入条漫接包会话并发送。安装版receive自动查同目录同集合分卷，不逐个询问、不手动拼包；缺卷或损坏列明具体序号。需实际可访问原目录，不能把孤立上传副本视为已收到全套。明确只检查时不启动生产。新接收运行的最终成品合同为无容量上限、必含两份问题CSV；前期运输容量不传递为成品限制。

## 接包技术兼容与原运行恢复

receive默认单话审计技术超时900秒，可用`--audit-timeout`覆盖，所有话仍共享原职责累计预算。超时、内容HOLD、读取版本冲突及进程异常分别报告；原始stdout/stderr保留。恢复使用`comic_start.py receive-resume --run-root <receive返回的职责目录>`，不重新解压、bind、建RV或开时钟。成功审计只有完整内容读集重新核对后才能复用，缺读集的旧报告重验；已有许可或调用时返回原生产入口，不把旧接收审计当当前调用许可。

receive返回`runtime_compatibility`及每话`generation_host`。先据结果使用配套冻结执行器；旧普通job不能传给新版强制submit执行器。未知冻结协议在实际调用前HOLD。首次兼容旧commit实现只覆盖宿主已验证的冻结工具指纹，不能按版本号猜支持或伪造SUBMISSION_REGISTERED。

接收端自动检查规则本机地址能否供后续QA使用。原批准包保持不变，实际返回使用等价本地执行副本；规则内容和实际输入不变证明与原件保留。接收检查不能代替返回后的真实审图。
