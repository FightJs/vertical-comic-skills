# 首次使用与短启动入口

对用户只展示总控入口，不要求粘贴内部policy/门禁/规则说明。规则库随五件套安装在总控assets/rule-memory；无需第三个路径或GitHub账号。新项目只需脚本、资产和话号；书名不明确时集中核对一次，不能猜格数或把候选当批准。

## 执行环境

首次运行或解释器变化时，读取本机CODEX_HOME/skill-bundles/vertical-comic-skills/installed.json中记录的python路径；有效时用它运行脚本。没有安装记录时选择实际Python 3.12+，先运行scripts/runtime_environment.py。Windows无需WSL；不要尝试pip安装fcntl。所有CLI使用UTF-8输出，路径作为独立参数传入，不拼接shell命令。PowerShell调用含空格的解释器时使用`& "解释器路径"`。

prepare与receive会在创建RV前检查当前环境。实际生图能力另按当前工具定义核验。安装成功、运行检查通过、真实生图可用是三个不同结论。跨电脑只复用包内冻结内容，不复用来源电脑的Python或绝对路径。旧冻结包不支持Windows时回前期迁移重导，不在接收端热修。

依赖清单随Skill及新冻结快照携带于assets/templates/runtime-requirements.txt；环境报告返回实际清单路径。接收端缺依赖时用本机已选择的Python执行`-m pip install -r <清单路径>`，再重新检查，不依赖前期电脑的虚拟环境目录。

## 安装后的首次配置引导

用户说“第一次使用”“帮我配置”或仅调用Skill而没有提供完整输入时，先进入本节。不要要求用户先创建或找到“条漫Skill使用配置.json”，不要把长启动词或技术JSON交给用户填写。

1. 先检查当前项目`.comic/books`中的本书配置及用户已提供的信息。已明确前期制作/接包生产就直接路由；尚不明确时只问一次选“前期制作”还是“接包生产”。只补问缺项，不让已配置用户重新走首次流程。
2. 前期制作将缺少的信息合成一条清晰请求，允许用户拖入文件/目录或提供实际路径：书名、源脚本文件、该书资产目录、准确话号。话号可写E021–E025。书名只有可从可靠元数据明确识别时才预填并展示；不从模糊文件名猜作品或格数。
3. 用户可直接回复路径，不需要选择技术policy、规则库、并发合同或输出RV。项目使用当前已明确的工作目录，默认输出及内置规则自动设置；用户可选填输出位置和执行agent数量。没有项目上下文或存在多个可能的项目目录时集中核对，不能写到猜测的目录。
4. 自动把用户路径解析为本机绝对路径，检查脚本确为可读文件、资产确为可访问目录；错误只询问对应项，不创建假文件或继续使用占位符。接到其他机器的路径时说明需要本机路径，不机械拼接。真实脚本话号/格数仍由后续源审计核对。
5. 信息齐全后调用comic_start.py prepare自动生成本书profile、本次配置、新RV及冻结快照，只展示一张输入/保存位置摘要并继续原准备流程。普通路径摘要不增加一次确认；与既有本书路径冲突等真实差异才集中询问。配置生成不代表A/B或正文获批。
6. 接包生产接受正式ZIP路径或已解压包根目录；新版单ZIP的内置清单和正式发布证据由程序校验、书话从包内读取，审核人按用户明确要求记录。包不完整或不兼容时报告具体缺项，不要求填写源脚本/资产/技术JSON。

前期缺项时可这样询问：

```text
我来自动完成首次配置。请提供以下缺少的信息：
书名：
源脚本：拖入文件或提供路径
本书资产：拖入文件夹或提供路径
话号：例如E021–E025
其他设置先用默认值；如需指定输出位置或agent数量，可以一起说明。
```

用户首次启动只需：

```text
使用 $vertical-comic-preproduction。
第一次使用，请引导我配置，进行前期制作。
```

配置成功后告知“本书路径已保存，以后只需书名和本次话号”，同时给出本次实际profile和运行目录，不声称已完成剧本审计或图片验收。首次制作无需登录GitHub、选择规则同步或开启自动上传；那些只在用户明确维护规则并选择同步时处理。

## 前期端

先按[任务来源](task-origin.md)区分独立制作与恢复。prepare只创建新任务，已明确重新制作不因旧工程存在而改走续做。使用保存的书配置只复用脚本/资产路径及偏好，不继承旧成图或返修账；可选request-source保存真实用户原话，不增加用户技术填写步骤。

首次：

```text
使用 $vertical-comic-preproduction，进行前期制作。
书名：【书名】
脚本：【脚本路径】
资产：【资产目录】
话号：E026–E030。
输出位置：【本机输出目录】
其余使用默认配置，完成后只交一个正式交接包.zip，交接说明与校验清单内置。
```

已有本书配置后：

```text
使用 $vertical-comic-preproduction。
前期制作：【书名】E031–E035，使用本书配置。
```

执行者把自然语言映射到`scripts/comic_start.py prepare --project <当前项目> --book <书名> --episodes E026–E030 --script <首次路径> --assets <首次路径>`；无需用户学习CLI。profile存项目`.comic/books`，本次话号保存在新RV任务配置，不写回本书默认话号。默认输出为项目/条漫输出/书名/首末话号/全新RV，输出路径或worker数量可由用户临时覆盖。初始化只建未批准模板与唯一运行快照，之后必须核对真实源稿格数/格序并正常推进A/B；不调用正文生图。

同书已配置路径与用户新路径不同则集中核对，不静默覆盖；旧comic_usage_v1显式memory_root继续读原库，不升级正在运行RV。新简易入口使用内置+用户增补；维护完成后只影响新运行。原A、最终B/包、高风险/H001/D及条件ZIP导出批准按当前任务模式执行。

## 接包端

```text
使用 $vertical-comic-preproduction。
接包生产：【正式ZIP路径或已解压包根目录】。
输出位置：【本机输出目录】
审核人是我，其余按包内流程执行。
```

执行者使用安装版`comic_start.py`：ZIP调用`receive --zip <正式ZIP>`，提前解压的目录调用`receive --package-root <包根目录>`。目录根包含`ZIP文件清单.json`和`交接验收索引.json`；若用户给外层解压目录，先定位唯一包含两者的直接子目录，多包才询问选哪一个。新版只需一个正式ZIP，内含交接说明、文件哈希清单和演练/导出证据；校验、解压、bind及rehearse按顺序执行。`--output <本机输出目录>`可指定输出位置。默认在ZIP或包根目录旁的接包生产目录建立全新RV。已解压目录只读使用，输出留包外；清单/大小/SHA256和发布证据通过后照常bind/rehearse，不寻找原ZIP、不重压、不重签。目录接收报告注明未核验原ZIP容器CRC，不把这一点当作阻塞。书话范围从包内读取，用户指定子范围时必须核对后建立相应范围任务，不能偷偷截断整个包。通过后进入原生产许可/窗口，H002不提前提交。旧版ZIP仍要求精确同名.zip.sha256；新版无需外部文件，也不套第二层ZIP。缺发布证据或旧包无运行模板时准确报告，不猜替代文件、不伪造绑定批准。

首次只给用户看一张输入摘要和当前确需处理的差异；审查页合并展示B与包但分别记录决定。extract/bind/rehearse及各项技术PASS留在内部日志，不要求用户逐命令确认。身份、动作、画风、场景及实际图片QA依然由阶段Skill负责。

## 后续更新

安装成功后告诉用户：以后说“检查并更新条漫Skill五件套到最新稳定版”即可，详见[安装更新](installation-update.md)。只在明确要求时查询/更新，不在每格生产时检查网络；无需重复填写本书配置，也无需GitHub登录。
