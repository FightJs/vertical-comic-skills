# Codex本地参考路径预算

2026-10-12本项目实际收到 `referenced_image_paths must contain at most 5 paths`。当前 `codex_builtin_imagegen` 编译/提交按最多5条路径执行；这是本入口观察到的限制，不是其他API或后端的通用上限。公开工具定义没有写明也必须执行已观察限制。若未来入口有真实变更，先更新能力证据与本合同/校验，不靠改执行包字段绕过。

每次生成、返修和资产候选调用都先数实际传入路径，再提交。5条是每个请求的参考路径数量，与每话并发图数、半话长度和agent数无关。半话并发额度保持原配置。

## 编译时先合并同图用途

`reference_images` 中同一实际文件只注册一次、一个别名；用多条 `reference_bindings` 保留全部获准用途。不按“身份、衣装、画风各一槽”重复上传同一人物板。相同图片哈希但文件路径不同也优先复用一份已核对文件；合并前核对来源、归属、所选状态及批准，不能把不同状态/不同图片误当相同。

例如一张批准人物板同时承载身份与画风，只保留 `@ID_A` 一条路径，分别绑定identity和style；另一张板同时承载身份/当前衣装，也只保留一个别名并绑定两种用途。人物与当前衣装不能因缺槽改为文字猜测；原批准画风仍实际随调用传入。多用途不扩大任一种允许迁移字段。

编译顺序：

1. 从获批当前镜头列必需角色/衣装、画风、场景、真实依赖输出及本次编辑目标，选最少的适用实际文件。复用同图多用途；不用独立“风格副本”重复同一图。
2. 合并别名后，保持subject_ids/subject_states及原批准证据，更新对应reference_bindings、style_contract.reference_aliases和适用composition_reference。其他设计字段需要变动时回受影响A/B形成真实新版本。
3. 用reference_usage_block重新编译实际序号；用style_block同步画风执行块。最终prompt、prompt.txt、单格JSON/manifest、调用计划与实际referenced_image_paths保持一致，不能只删工具数组第六项。
4. 已冻结的旧包只留历史，新包另存版本和真实哈希，generation_execution=NOT_RUN。生成前重新走完整门禁；上限/重复检查不代替身份、画风、空间、规格、记忆或批准检查。

超过5个不同必需文件时，返回REFERENCE_LIMIT_HOLD，只暂停受影响格。先用足够且已批准的多用途人物板/场景参考；可用 faithful_atlas_v1 将原批准人物/衣装按原尺寸裁区忠实排入技术图集，逐人物保留原批准、状态、来源与像素核验；这种排布不产生新视觉批准，也不能作为画风来源。合同见 [execution-compatibility.md](execution-compatibility.md)。确需重绘的合并参考板仍由visual-assets准备候选并获得适用批准；若作为画风来源，其实际哈希也须被批准。不要缩小脸/服装到无法辨认，不拼入标注站位图作为摄影机参考，不减少必需人物/衣装/场景/依赖来凑数量。站位图等审阅文件按原规则放supporting_documents，不占生图图片槽。

## 门禁与实际提交

codex_reference_contract.validate_panel默认检查最多5条和重复实际路径；超限不返回工具计划。check_control_inputs的preflight和完整generate门禁继承检查。async_generation.js另检查实际job.arguments.referenced_image_paths，超过5条或重复字符串在invoke前停止，不能宣称已发出工具请求。把不合格条目留在待重编译队列，合格独立条目经许可正常提交。

旧文件的执行/图片验收按其原始实际请求、返回和质量证据核验，不以今天的提交预算改写历史。历史审计不开新请求；当前新调用/计划导出始终执行新预算，不因旧execution=COMPLETED豁免。旧返回证明真实完成也仍须全部实际图像QA与当前适用性校验。

## 参数拒绝与恢复

这类拒绝属于调用输入问题，不是视觉失败图；没有图不写GENERATED，不增加视觉失败数或当作第二轮修图。保存原错误、实际来源、attempt、许可与输入数组；处理CALL_HOLD时先核对是否明确拒绝且确无图。已经返回或结果未知不能重发。需重新提交时先在新执行包修正输入、重新检查并领取合规许可，不复用失败attempt或伪造完成日志。已存在成功重编译结果时直接进入验收，不重复生成。

工具额度属于后端能力合同；规则记忆库保持跨作品通用方法，不把本次E025状态/错误写进规则库。

可见首饰需要单独参考时先复用足够清晰的原板；忠实图集裁区必须实际覆盖该细节source_region，同源哈希但裁掉耳环不能视为已携带。按 [具体视觉证据](visual-evidence.md) 绑定，不因此超过五条路径。


多视图选区与实际细节覆盖见[实际执行质量与返修分流](execution-quality.md)。复用现有记录和人工停点，不静默升级旧RV。

## 忠实图集的有效细节

像素忠实不等于细节可辨。本格依赖图集中的小饰品、衣领或身份特征时，在原ref可登记detail_readability=[{subject_id,detail_id,region,status,observed}]；region是图集实际整数像素框，须属于该人物/用途的assembly_region，status只能在实际看清后填PASS。此观察不替代资产批准和正文实图验收。看不清则调整选区/排布或使用足够清晰的原板，不重绘未知设计或单靠放大。普通不依赖小细节的图集不新增此表。


服饰细节按[定位合同](appearance-and-single-frame.md)核验原裁区、身体归属和costume_state用途；看不清耳部的全身图不能因为“同人物”就视为清晰细节约束。最多5条路径不变；在同一输入内忠实组织局部图集，不丢关键细节或另画不忠实参考来凑数。
