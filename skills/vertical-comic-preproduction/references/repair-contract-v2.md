## Repair without false release

Before any output directory or prompt is created, run the scoped identity/state/scene preflight in [identity-confirmation.md](identity-confirmation.md). Missing migration, unresolved aliases/relationships, unknown appearance state or mismatched asset ownership must stop with the relevant HOLD. `--accepted-basis` authorizes only its recorded scope; it cannot manufacture identity approval or waive the preflight. Preserve the registry and panel bindings in the repaired index, JSON and actual identity execution block. `--identity-root` selects the episode evidence root (default: source package parent).

1. Build a book/episode-bound inventory. Compare exact source-script hashes, panel count/order and all source cells. Do not trust existing `script_lock_check=PASS` without comparison. Do not infer book identity from reused asset IDs: IDs may overlap between books.
2. Reconcile old HOLDs against later scoped user acceptance and actual files. Record source and evidence hashes. Authorization to repair is not approval of new designs. Preserve both old facts and resolution evidence.
3. Count actual visible appearances by canonical entity (same book, across available episodes). One visible occurrence requires no standalone asset. Recurrence within one scene or one episode is still recurrence. Offscreen speakers, “电话”, “包内”, and “楼下声音” are not automatically visible characters. Unknown identity is not resolved by declaring a character one-off.
4. Apply the user's 2026-10-09 information-first framing policy: motivated same-scale shot/reverse-shot and reaction coverage are allowed. Preserve approved cameras and crops; do not rotate scale/angle presets or widen dialogue just for alternation. Verify actual focal subjects, view, crop and script-supported visible beats; a signature edit alone proves nothing. Unchanged composition without an observable change needs explicit pair-specific approval. If a new crop would omit locked action, props, text or required simultaneous reactions, keep the conflict open.
5. Read nested camera structures. Ratios come only from positive structured ratio fields or an explicit reviewed visual design; never from negative-prompt text. Do not silently substitute 3:2 or force every panel to 9:16.
6. Derive screen contents from scene and blocking. Relative coordinates suffice. A new map does not establish approval. Camera height/direction, visible face fraction, screen placement, background and occlusion must agree. Structured declarations or circles selected without scene evidence are not geometric proof. Record visible facts in the shot JSON and actual prompt; for Codex, preserve or prepare a reviewed clean target-camera composition reference when needed, following `codex-imagegen.md`; never manufacture a text screenshot or promote a retired card by renaming it.
7. Write a single concise executable prompt. Include necessary content, not filler to hit 600 characters. Separate immutable script text from render instructions; narrative dialogue stays outside image generation, diegetic text stays in the image. Unknown exact diegetic text is not permission to invent it or remove required information.
8. Copy actual PNG/JPG (or B-supported raster formats) and cite every reference alias. Retain SVG/JSON in audit files; rasterize genuine station SVGs only when useful and supported. Do not turn JSON or text into reference images, or fabricate a substitute when actual references are absent.
9. Read the delivered prompt file, not merely manifest text. Prompt file, per-panel JSON, camera fields, reference hashes and package index must agree. Do not copy stale old prompt JSON, ZIPs, READMEs or old READY flags into the executable folder.
10. A package containing open holds is not READY even if a structural script passes. Separate fixable technical defects, user decisions, new-design approval and post-generation image QA. Do not require final images to release a valid prompt package; require image QA before C-stage layout.

## Evidence records

- One-off exemption: kind, canonical ID/name, visible panel IDs, occurrence count, scanned script scope, aliases checked, script-supported literal design description. Only the standalone-asset requirement is waived, not text/spatial checks.
- Approval resolution: issue, affected panels, user-event path/hash, accepted scope, actual reference paths/hashes, result. Do not resolve all spatial issues using an asset-only approval.
- Camera revision: before/after angle, scale, actual position/facing, subject extent, background change, narrative reason, dependent maps invalidated/rebuilt, status.
- Output: `修复覆盖台账.json`, `未决项.md`, new package, new reports, original hashes, shared-skill tests. Report incomplete work plainly.
