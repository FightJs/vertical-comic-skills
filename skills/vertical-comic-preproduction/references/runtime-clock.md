# 三小时效率目标、四小时有效运行硬限

新正式入口默认启用three_hour_target_four_hour_active_v1。前期、接包生产各自从入口开始建立一个职责时钟，多话共用同一额度，不按话数重复发放。默认14400秒累计有效运行硬限，可按用户要求缩短；不得自动延长。明确暂停、等待用户不计时，恢复后接着累计；生图服务等待、编译、检查、审图、返修、打包均计时。旧冻结运行按原协议恢复，不重置历史。

三小时是效率目标，目标争取至少80%的完整前期/生产职责运行在10800秒有效运行内完成，**不是生图截止时间**。超过三小时仍可继续生图、返修和审核，只要未达到四小时硬限且原门禁有效。

- PRODUCE：复用已有内容哈希校验、逐格增量编译、按真实依赖并行、返回即保存、滚动QA及交付归集。不要逐格重启解释器、重审全话或为状态字段改动反复重建批准。
- 有效运行2.5小时进入CONVERGE：停止可选润饰和重复展示（工作请求标注`optional:true`时由工具拦截），优先消除共同原因、清理已返回图审核队列、增量核对源格和交付索引；必要生成和QA继续。
- 有效运行3小时进入TARGET_OVERRUN：标出超目标原因及编译/等锁/服务/保存/审核/登记/打包分段耗时，继续必要生产和修复；不触发禁生成、不降低QA标准、不提高并发掩盖阻塞。
- 有效运行4小时HARD_STOP：拒绝新执行步骤、QA登记和交付发布，保留恢复点及缺项。已发请求仍可安全收存、记为返回或未知；不清除登记、不自动重发、不把迟到结果宣称为按时完整交付。

强制边界在已接入的本地调度、提交、审核、交付入口；长校验协作检查，已有受控子检查按剩余预算终止。不能保证远端服务被物理终止，也不能把到限停止等同于全部图片生成完成。暂停记录依赖原可信宿主/显式生命周期，不伪造暂停来扣除正常工作。

## 新运行

`comic_start.py prepare ...` 或 `receive ...`（默认`--runtime-limit-seconds 14400`，只允许缩短） 在本地运行的 `00_任务协调` 建立 `runtime-clock.json`。入口开始即采集真实时间戳，之后建立账本并记录start时保留该起点；分卷恢复递归沿用同一时间戳，不重复发放预算。入口调用之前的会话分析不在自动计时范围，不能宣称覆盖整个会话，也不得事后猜测补时。

启动入口自动核对当前进程的 `CODEX_THREAD_ID` 与新近PreToolUse Hook收到的真实 `session_id`，再把会话绑定到返回的 `clock_directory`。使用人员不填写session_id，不手动执行bind。没有可信Hook回执、身份不一致或回执过期时返回明确错误，不创建一个未绑定却声称自动暂停的计时运行。宿主若不提供上述身份链路，自动模式不可用，不按最近目录猜测。

同一职责只有一个活动owner，同一会话不能接管另一个未完成RV。同一会话顺序完成前期后可启动生产；真实完成时解除活动绑定并保存历史。普通进度查询不会恢复计时。

## 安装与界面停止接线

安装器将独立Python及必需依赖放入 `$CODEX_HOME/skill-bundles/vertical-comic-skills/runtime/`，安装记录指向该解释器。环境采用本机Python基础安装，不依赖下载仓库里的venv；删除下载目录不影响执行。基础Python本身被卸载时运行检查会报错，使用有效Python修复环境。

首次接线使用 `tools/sync_skills.py --clock-hooks`；已配置条漫Hook的后续更新自动迁移。也可由执行者运行安装版 `runtime_clock_setup.py --apply` 修复失效解释器。先备份再替换本Skill的旧命令，保留其他Hook。稳定环境可用时复用，不每次重建。

配置三个事件：SessionStart记录宿主身份；PreToolUse仅为条漫启动/计时/恢复命令或已绑定任务更新身份回执；Interrupt快速记录暂停。Hook不会在用户发送普通消息时自动恢复，不运行生产、不改批准或预算。记录的是收到事件的时间，不冒充精确按钮点击时刻。

非管理Hook须在Codex中审阅并信任准确的定义，安装器不能代替宿主信任。定义变化后可能需重新信任；所有普通运行不再重复询问。官方说明：https://learn.chatgpt.com/docs/hooks 。配置存在、脚本测试通过、真实会话回执收到、已绑定及真实Interrupt收到分别报告，不混成一个PASS。

真实点击停止尚未验证时不宣称自动扣时已验证。没有支持或信任时明确说明原因；需要显式暂停的旧任务仍可使用 `runtime_clock.py pause --directory <目录>`。不能根据消息间隔或心跳缺失推断暂停时间。

## 恢复与查询

- 人工暂停后只问进度：查询status，保持PAUSED；不自动恢复生产。
- 用户明确恢复原任务或授权继续实际工作：先运行task_coordination.py resume核对旧任务/未知请求，然后 `runtime_clock.py resume --directory <目录>`，再继续；resume会自动核对并续接当前会话。不同会话恢复须先明确交接owner，不能静默抢占。不重置attempt、调用、额度或历史事件。
- 明确等待用户：wait_user；得到必要答复且恢复实际执行时resume。
- 多次相同event_id幂等，冲突动作拒绝；不同ID的重复pause/resume不会重复扣时。
- 已通过真实完整交付校验后记录finish；未完成但停止工作时pause，不用finish伪装完成。
- 启动标识为空不视为同一启动周期：按可核对的事件时间检查相邻区间，单调回退或时钟冲突保持TIME_UNCERTAIN。confirmed_closed_seconds只表示异常前已确认的闭合有效区间；不确定时active_seconds与remaining_seconds为未知，不能用下界重新发放额度。旧事件不补造启动身份。
- 单调时钟与墙钟共同核对时间；可取得boot标识时校验重启。宿主/boot变化、计时不连续或墙钟明显跳变报告TIME_UNCERTAIN，不伪造精确时长。异常退出且没有中断事件不能自动扣除离线时间，需核对时间证据，不能重建账本清零。

## 暂停与生产边界

新工具在领取及IN_FLIGHT登记边界检查计时。暂停、未开始、时间不确定或额度用尽时不新增领取/调用；原来已提交的远端请求仍可能继续且计费，允许保存、查证及落账。恢复前先查证，禁止重发未知请求。最后一次检查到外部工具实际接收之间仍存在宿主调用边界，不能承诺撤回已发出的请求。

旧冻结工具不热替换，也不会因为上层新账本自动获得所有检查；接包使用旧冻结入口时，总控必须在实际工具调用前用安装版 `runtime_clock.py check-submit --directory <目录>`。该返回只允许紧接着的一次调用，不保存为长期许可。外层Hooks不能在总控停止后保证所有旧工作agent/外部服务立即停止；须在委派时传入同一目录并要求每次提交前检查。尚未接入的调用路径明确标注，不能宣称全链路原子暂停。

生产指标分别报告自然经过/有效运行/排除区间；有效运行不等同CPU耗时或服务计费时长。旧协议到期仍保留原收尾能力；新硬限协议到期只保留安全收图/在途结果记账，不继续新审核或打包，迟到结果如实报告。总控据剩余时长提前预留收尾时间，不为赶时限跳过必要审核。

## 计时验证（仅明确要求界面接线时）

不生图：真实停止一次，间隔后明确恢复，核对Interrupt事件、累计秒数和暂停区间。另测重复事件、并行共用额度、暂停期间返回保存、到期拒绝新请求、重启/时钟异常。仅模拟Hook载荷不算真实按钮接线通过。

## 已有运行接入

仅接入用户明确指定的本地运行：执行安装版 `runtime_clock.py attach --directory <本次协调目录>`，自动核对当前会话。返回生效时间，保留原账本字节和全部旧事件，不倒推缺失暂停、不重置额度。旧owner仍活动时拒绝接管，先核实停止并显式unbind。已经完成的前期账本不重新计时。

正在生图的旧RV只加本地会话绑定，不替换包内冻结脚本。旧入口仍按下节检查要求在提交前执行安装版check-submit；不能保证未接入的旧工作agent自动停止。异常退出缺少事件时保留TIME_UNCERTAIN诊断，不将未知空档全部算作暂停。

新prepare/receive在本机保存local_execution_context_v1，状态绑定其文件哈希，记录准确累计有效时限和协议版本。低层旧调用允许的None只为兼容旧协议，不用于绕过新正式入口的默认硬限。应计时却缺账本、绑定失效、上下文丢失/换版均拒绝新请求，不能回退旧运行不限时。工作执行者共享职责时钟，不接管总控owner。正文/返修/资产在[统一提交登记](submission-runtime.md)内核对计时；排队/锁等待后重新检查。登记后被暂停时保留原登记并报告SUBMISSION_REGISTERED_NO_INVOKE，不自动退回PENDING或重试。
