# 从 screenwriting master 蒸馏的镜头设计方法

来源：`~/.codex/skills/screenwriting-master/SKILL.md`、`references/core-methodology.md` 和 `references/format-series.md`。本文件只移植有助于画面设计、镜头功能和连续性控制的部分；不移植改写剧本、重写对白或改变故事结构的权限。

## 1. 把已有戏剧动作变成可见证据

对每个已经存在的脚本 beat 做分析：

`目标 Goal → 阻碍 Conflict → 已有结果/转向 Result or Turn`

这三个字段用于决定镜头拍什么：

- 目标：角色正在做什么、看什么、等待什么或试图得到什么；
- 阻碍：什么人物、道具、空间关系、信息差或动作阻挡了目标；
- 结果/转向：脚本已经写出的成功、失败、反应或新信息。

不能因为镜头设计需要而补写新的目标、阻碍或结果。没有足够画面依据时记录 `VISUAL_HOLD`。

## 2. Show don’t tell 的画面化用法

只把已经由脚本事实支持的内容转换成可见动作：

- 手部动作、停顿、姿势变化、视线、物品接触、空间距离、遮挡和人物反应；
- 通过构图强调脚本已有的信息，而不是用新台词解释它；
- 不把“他意识到”“她其实很害怕”等不可见心理直接变成未经依据的新表情或动作。

如果心理状态没有动作、表情、对白或上下文证据支撑，保留原脚本，不擅自视觉化成新事实。

## 3. 双轨节奏用于镜头选择

为每个段落和格子标注两个维度：

- 外部情节强度：松 / 中 / 紧；
- 内部情感强度：轻 / 中 / 重。

两条轨道可以错位。例如“情节松、情感重”适合留出空间、减少信息拥挤、使用背影或局部反应；“情节紧、情感轻”可以使用更活跃的角度、动作方向或信息并置。该方法只能改变视觉重心和镜头语言，不能改变事件或台词。

不要让全话所有格子都同一种强度、同一景别或同一视距。也不要机械轮换全景、近景、特写；变化必须对应 beat 功能。

## 4. 信息功能和镜头任务

给每格登记一个主要信息功能：

- `ESTABLISH` 建立空间；
- `ORIENT` 交代人物关系和位置；
- `REVEAL` 展示脚本已有的新信息；
- `REACTION` 展示已有动作的反应；
- `ESCALATE` 强化已有冲突；
- `CONTRAST` 对照两个已有信息；
- `BREATHE` 给已有情绪留空间；
- `HOOK` 强调脚本已有的开场或结尾钩子。

信息功能决定景别、空白、遮挡、视线和节奏，但禁止额外制造信息。

## 5. 连续剧式记忆转为漫画连续性

每个角色在每格登记：

- 物理状态；
- 当前情绪的可见表现；
- 已知信息；
- 当前行动目标；
- 需要延续的衣物、伤势、发饰、道具和视线锚点。

每个场景登记：

- 固定空间结构；
- 已公开或已展示的物品和信息；
- 当前仍在运行的线索；
- 前一格留下、下一格必须承接的画面关系。

这套追踪只能防止穿帮，不能把连续性表里的推断写回脚本。

## 6. 场景和集末功能

从剧集方法中只吸收“每个场景/段落要有功能”和“前后承接要清楚”：

- 场景开头建立或承接真实空间；
- 场景中段让已有冲突、信息或关系推进；
- 场景结束承接已有结果或钩子；
- 相邻格和相邻场景的节奏需要有波浪，而不是整话同密度。

不要因为需要“更抓人”而新增悬念、台词、转折或剧情。
