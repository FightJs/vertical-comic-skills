# 整话生产与状态合同

前期询问策略先按[明确委托的最少询问规则](grouped-review.md#前期仅询问无法消解的剧本资产冲突)判断；适用时，本页前期亲审/确认均改为执行者实际审查和委托决定，导出沿条件授权执行，不增加人工停点。生产阶段及旧冻结合同不因此改变。

新运行统一按[第一批生产决定](production-decisions.md)衔接审核、返修与交付：真实FAIL不改写，处理动作与交付结论分别记录；旧冻结合同不迁移。下文审核方法、源稿/批准/证据要求仍适用。

新任务使用 episode_async_v1、episode_preparation_v1、panel_readiness_v1 和 incremental_runtime_v2。固定流程为输入审计 → A视觉基准 → B镜头与生图包合并审阅 → 整话并发生成及滚动自审返修 → 整话连续性与跨话比较 → D最终验收及逐格图片包。没有固定半话C或首五格试产停点。

旧RV仅按原冻结合同恢复，需要字段细节时读[旧状态合同](staged-workflow-legacy.md)；新任务不加载旧半话、首三格或首五格推进指令。当前具体调度和预算见[整话异步](episode-async.md)。

## 唯一来源

生产流程根保存 source_script、source_snapshot、visual_basis、shot_manifest、semantic_audit、批准索引、panels及真实调用记录。batch_plan仅有EPISODE；不复制half_inputs/half_gates。源格号、源序、原文及标点保持；无损执行映射保留原依据。

文件引用为相对其明确所属根目录的path/sha256；话内引用不得越界。不同包内引用按包根解释，不以重命名或换路径扩展批准。调用前冻结真实输入，返回后追加真实执行证据；旧请求、失败与取消记录保留。取消不自动恢复。

## 人工批准

人工节点保留A、B与包、必要高风险状态和D。按[合并审查](grouped-review.md)一次展示就绪事项、一条明确回复分别登记批准；不等其他话、不因进度更新重复提问。输入冲突尽量随A处理，关键未知仍须具体裁决。

批准记录必须有status=APPROVED、source_kind=user_message、真实quote/source_locator、book_id、episode_id或episode_ids、准确panel_ids及artifacts文件版本。模型观察、程序PASS、配置与沉默均不授予用户批准。复用已有原范围和原版本证明，不伪称用户重新确认。

A覆盖源稿、源快照和视觉基准；B覆盖视觉基准、镜头及适用全话语义/画幅依据；包批准独立覆盖准确实际输入或冻结依赖补齐方案；高风险确认绑定实际返回图；D覆盖整话当前图、QA与适用跨话比较。最初整话制作请求可作生产授权，不能替代以上视觉批准。

## 生成与验收

先完成候选B及包的实际核对，再合并交审。仅完整预检通过、获准确授权且输入依赖满足的格可提交。只有generation_dependencies要求先有真实QA通过的前格图片；设计连续性不自动等于图片输入依赖。

返回立即保存，保存回调不填PASS。执行者实际看原图及必要参考，一次观察填写六项QA和命中规则；细节不清楚看原尺寸局部。局部未审和连续性待补分开记录，最终验收前必须补齐。明确身份、衣装、动作接触、固定空间或画风错误仍FAIL。

首轮失败按最早失败层诊断；执行失败可滚动使用本格唯一第二轮，超过五张真实视觉失败先做共因诊断。二轮仍失败停止自动尝试，比较采用版本并记录遗留；仅仍有重大问题且存在实质不同方案时按授权集中处理追加范围，不无限抽图、不重置原轮次。改基准/镜头/实际输入时只回准确受影响范围。未知返回先查原请求，不把超时当成未执行。

## 运行版本和交付

按[批次运行](batch-runtime.md)创建本批唯一共享快照、固定规则正文；各话从快照scripts运行。总控分配容量租约，本话单写请求账本与状态，避免逐请求根握手。旧permit模式仍按原合同，不向旧RV静默添加新字段。

本话本地审查完成后交回图、QA和待比较边界；总控补跨话比较并组织D。原D/委托决定前称待阶段交接确认；新deliver核验原QA与采用问题去向后按源序导出，旧RV保留原严格验收。最终交独立PNG、索引和验收依据，不拼接、不加气泡；源稿要求的画内文字仍须正确。
