# 任务来源与历史适用范围

在任何目录搜索、历史对账或资产决策之前读取本页。任务来源独立于“分工制作/一机制作”等职责模式。用户当前明确指令优先；同书同话、相同脚本、已有旧图或新建RV均不能自行决定是否续做。

| 用户实际要求 | 处理 | 历史范围 |
| --- | --- | --- |
| 重新制作、只根据脚本与资产、新前期准备 | fresh：独立任务 | 只记录本任务实际调用，不搜索、导入或索要其他任务的图、QA、追加授权和预算 |
| 恢复、续做、继续某个原RV | 原任务恢复 | 从原冻结状态读取，保留原任务身份、attempt、UNKNOWN和预算 |
| 明确复用某些旧图/旧成果 | reuse_selected：准确导入 | 只核对被选择的成果及其真实依赖，不扩成全书历史追溯 |
| 接收正式交接ZIP、跨机迁移 | 原任务接收 | 保留包内任务身份；地址改变不改变调用与预算 |

“前期制作某书某话，使用本书配置”在没有恢复或复用指向时走fresh；配置提供源路径与运行偏好，不代表继承生产历史。已明确重新制作不再询问。只有同时要求重做与续接相同成果等真实矛盾时集中澄清。独立重做不追索其他任务服务请求；同一任务的真实UNKNOWN始终保留，不能借重建目录绕过。

## 新任务的可执行记录

新入口comic_start.py prepare生成task_context（task_scoped_history_v1）：task_id、book_id、准确episode_ids、origin=fresh/reuse_selected、input_scope=script_and_assets、request_source、imports。用户原话用真实source_kind=user_message、quote、source_locator；可选--request-source传JSON。没有人类消息的程序调用记tool_invocation，不能冒充批准。复用另用--reuse-selection传用户已明确选中的source_task_id、episode_id、panel_ids及包根相对path/sha256证据；不能自动发现旧成果或仅因同名就导入。

总控任务来源与各话state.task_context相同。各话00_输入审计/任务来源.json保存真实初始化事实（正文/资产初始调用为0），不是A/B批准。正文后续按原运行账和attempt_history记录；资产调用按A原记录另列，正文为0不能写成全部生图为0。缺字段不由用户手填，执行者从真实消息和运行事件建立。

恢复与接包保留原task_context与来源文件；不调用prepare重置原任务。底层init_preproduction对已有整话生产流程无修改返回，明确提供不同任务身份时拒绝；不覆盖来源或预算。老RV缺本合同时仅按原冻结工具运行，不补造任务身份或重签旧证据。

## 有限输入审计

fresh只读取指定脚本、当前全面资产包、适用包内批准及本批冻结规则。索引中的历史绝对路径是追溯信息，不是执行搜索指令。不得因为它失效就遍历旧生产目录、回收站或其他任务。若存在明确选择的旧成果，才在其准确范围读相关历史。

先从实际源格确定需求，再核对有效资产索引及真实图片；多个旧索引是版本证据，不把每条历史记录都当成当前必需依赖。缺路径依次判断：本次是否使用→当前资产是否已覆盖→是否有同内容/同状态的有效依据→确需补什么。未使用缺项不阻塞本批；旧批准外链失效与缺少当前必需图分开。包内原话/范围/内容哈希等有效证据可作为确认依据，但只有APPROVED标签或文件名不足以证明批准。

本批资产闭合只核本批需求；发布新资产到全面资产包时另执行发布前的全书索引对账，保留已知库缺口，不宣称全库完整。旧扫描缺失时按当前可读输入重建本轮扫描，不要求先找回旧生产工程；真实缺口只影响对应资产和依赖格。

## 交接门禁

交接索引顶层携相同task_context；history.task_id限定本任务，逐次attempt.task_id为本任务或已选择导入的来源任务。NEVER_SUBMITTED仅指本任务本格尚未实际提交，不表示该书该格从未生成过。

handoff_zip从真实运行模板读取任务来源、逐格状态和保留attempt_history核对账本；空数组不是零调用证据。已提交、在途、返回、失败与未知都必须列账；当前任务UNKNOWN、预算不符、历史被删仍HOLD。指定导入的旧图仍携原图、QA、验收与本次A/B适用性复核。未选择导入的独立任务不进入本次门禁。

最终输入摘要绑定任务身份及继承范围；bind/rehearse核对原任务，不能改写。解压、真实冻结门禁、准确批准、高风险实图、H001与D审核及单ZIP正式发布要求不变。
